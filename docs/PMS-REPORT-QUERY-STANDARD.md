# PMS 报表查询模块规范

## 已落地范围

2026-09-24：第二版交互样稿获批，接入即时库存、采购进度、物料收发明细。视觉基线为 `frontend/prototypes/report-query-v2.html`；本批仅开发机实施，不代表服务器已发布。

## 页面标准

- 使用现有PmsDataList承载工具栏、表格、滚动条和分页，不重复大标题。
- 工具栏左侧放PmsReportPlans，右侧放状态、导出、列设置。列设置继续使用PmsListColumnPicker。
- 快捷条件使用PmsReportQueryBar和统一表单控件，输入框、方案选择、按钮统一32px高度、13px字号；不另占一行放标签，使用明确占位内容和可访问名称。查询、重置、添加条件紧随输入区，不隔着大块空白靠右。
- 共享样式入口为 `frontend/src/report-query/query-surface.css`，页面显式使用 `pms-report-query-surface`。常规选择框140px、物料220px、日期区间250px、方案180px；窄屏自然换行，不隐藏必填条件。表格密度不随查询区调整改变。
- 三张报表均使用PmsReportConditions浮层添加条件；应用只更改草稿，取消不修改。按后台白名单呈现文本、数值、日期和枚举的控件与运算符；条件最多20项。仓库保留候选选择，不开放自由文本条件替代。
- 列名悬停仅显示中文名称，不展示后台字段编码、SQL取值或来源说明。
- 条件浮层内的选择菜单、枚举菜单和日期面板统一挂载到当前条件浮层容器，不能挂到外部后被误判为点击空白；挂载点在滚动行容器外，避免裁切。浏览器验收必须覆盖鼠标点击伸出父浮层的选项，不可只测试默认字段或键盘输入。

## 查询行为

1. 初始化只加载元数据、权限、偏好和保存方案。候选按需请求；不调用主报表查询。
2. `createReportSession`管理草稿、成功条件快照和请求序号。点击查询复制草稿；仅成功且未过期的响应可以更新快照及结果。
3. 编辑、应用高级条件、重置、选择方案都不查询。重置和选择方案须失效正在执行的请求，并取消请求。
4. 翻页和排序使用已查询条件；没有成功查询时不发请求。导出使用上次成功请求参数，权限由后端实时复核。
5. 失败保留上次结果并明确提示，不能把新条件标为已执行。存在草稿变更时，导出确认提示上次结果。
6. 查询方案的每页条数在下一次查询成功后生效，不能只改旧结果的分页标注。

## 方案与兼容

- 方案按用户、报表独立保存到浏览器；包含version、名称、条件、可见列、顺序、冻结、宽度及每页条数。不保存权限或登录凭据。
- 即时库存原先只有列偏好，无查询方案。保留原v1列偏好键，新增独立`:plans:v1`键，不丢弃已有列布局。
- 方案引用失效字段、无权限组织或非法条件时拒绝应用并提示，不静默删除条件而扩大查询范围。
- 采购和收发保留各自旧存储键；采购旧方案的进度条件转换为枚举条件。无效条件必须提示，不能直接用库存键替换。

## 库存类型能力

- 文本：包含、不包含、等于、不等于、开头是、结尾是、为空、不为空。
- 数值：等于、不等于、大于、大于等于、小于、小于等于、区间、为空、不为空。
- 数量空值只匹配NULL，不匹配0；文本空值匹配NULL或空字符串。反向比较不自动包含NULL，需用空值条件单独查询。
- 值必须参数化，字段及运算符必须白名单。列表、计数、导出共用inventory_reader；组织授权约束始终保留。
- 当前库存组织和仓库保留现有单选接口。物料收发支持多组织，物料、组织必填；为空或条件无效时禁止查询，后端同样拒绝。

## 收发计算与导出

- 收发先按物料、组织、日期、仓库计算完整期初和流水结存，再对已算好的流水应用新增条件。不得先过滤单据再计算结存。
- 附加条件只筛选展示行；期间汇总和期初保持基础范围，并在界面明确标注。过滤后的行间结存不保证连续，不应据此重新加减。
- 采购列表、总数和导出采用同一条件，采购进度枚举使用既有采购计算结果判定；多批订单和入库不改变原有核算逻辑。
- 收发数量保留两位小数，0与空值均留白；显示留白不等于数据库把NULL转换成0，空值筛选仍保留区别。

## 接入验收

覆盖零自动查询、无效条件、零值/空值区别、方案恢复、分页、排序、导出、失败保留、旧响应失效、权限撤销及响应式布局。前端执行report-query-state、库存浏览器、三项UI契约和build；后端执行库存与导出、数据权限测试。模拟测试不等于金蝶真实对账或正式发布。
