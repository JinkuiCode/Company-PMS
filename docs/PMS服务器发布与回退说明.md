# PMS 服务器发布与回退说明

## 适用范围

本说明用于把已经在开发机通过验证的 PMS 发布候选包同步到 `10.10.1.228`。发布包只包含后端程序、固定依赖清单、金蝶官方 SDK 和前端生产文件，不包含服务器运行配置、数据库、日志或用户上传数据。

本说明是通用发布步骤，不代表任一候选包已经部署。现场状态以 SOP 和本次批准范围为准：2026-09-14 已开放生产金蝶日常同步（K3_READ_ONLY=false）；后续维护不能因旧版只读验收文字而长期关闭已批准的日常同步。

发布包同时包含 `ops/windows` 运维模块。模块存在不代表计划任务已经安装；正式服务器安装、重启验收和数据库恢复演练仍需单独维护窗口。

## 制作确定版本的候选包

先审查并提交部署相关源码、前端完整目录、发布脚本和本说明。运行 `./build-server-release.command --output-dir release`，也支持绝对路径。工具拒绝未提交的构建输入，不再支持 `--skip-build`。

前端从确定提交的临时目录重新构建，使用开发机按 lockfile 安装的依赖；后端与本说明均从同一提交读取。已有 dist 不参与打包，也不会被改写。Git commit 与 SHA256SUMS 分别用于核对源码版本和文件完整性。候选包不包含运行配置、数据库或测试文件。

## 部署前只读核对

重新连接服务器后，先记录并核对以下信息，不立即覆盖文件或重启服务：

1. PMS 实际运行目录、后端进程命令、Python 解释器和服务启动方式。
2. 当前服务器代码版本、前端首页引用的资源文件名和工作区状态。
3. 受保护配置文件的位置、文件权限和环境变量优先级，只确认是否存在，不显示密钥内容。
4. 数据库类型、连接方式和数据文件或实例位置。
5. Nginx 实际配置、静态文件目录、监听端口和反向代理目标。
6. 最近一次可用备份及可用磁盘空间。
7. `PMS-Startup`、`PMS-Health`、`PMS-Log-Rotation` 三项计划任务是否存在、最近结果及实际脚本路径。

历史记录显示后端曾位于 `C:\PMS\backend`，Nginx 曾位于 `C:\nginx` 并通过 80 端口提供服务。这些只是上次检查结果，必须以重新连接后的现场核对为准。

## 发布包校验

1. 将 ZIP 和同名 `.sha256` 文件复制到服务器临时目录，不直接解压到运行目录。
2. 使用 PowerShell 计算 ZIP：

```powershell
Get-FileHash .\pms-server-*.zip -Algorithm SHA256
```

3. 计算结果必须与 `.sha256` 文件首列完全一致。
4. 解压到新的临时目录，核对 `RELEASE-MANIFEST.txt` 中的 Git commit。
5. 可抽查 `SHA256SUMS`，确认解压文件未损坏。

校验不一致时立即停止，不使用该压缩包继续部署。

## 备份

在确认目标目录后，为本次部署建立带日期时间的独立备份目录，并至少保存：

- 当前后端程序目录。
- 当前前端生产目录。
- 当前 Nginx 配置。
- 当前服务启动配置或计划任务信息。
- 当前受保护配置的原位备份；不得复制到聊天、Git 或普通共享目录。

数据库按实际类型执行适用备份。未确认数据库备份可恢复前，不进入覆盖步骤。

## 部署

1. 记录现场已批准的金蝶写入状态。按维护窗口安排暂停同步；如短时设 `K3_READ_ONLY=true`，记录原状态并在验证完成后恢复。初次未批准写入的环境继续只读，已批准的生产日常同步不可被模板永久关闭。
2. 确认没有正在执行的 ERP 同步任务，再停止明确识别出的 PMS 后端服务。
3. 使用发布包中的 `backend/app`、`backend/main.py`、`backend/scripts`、`backend/vendor` 和 `backend/requirements.txt` 更新程序文件。
4. 保留服务器原有 `.env.local`、数据库、日志和运行时目录，不使用模板文件覆盖真实配置。
   发布前先补充 `PMS_ENV=production` 和 `DEBUG=false`，使用 `backend/scripts/check_runtime_config.py` 只核对缺失项名称。不得把配置值输出到终端记录。
5. 使用服务器实际运行的 Python 环境安装或核对固定依赖。
6. 将 `frontend/dist` 作为一个完整目录切换，避免新旧资源混用。
7. 更新 `ops/windows` 运维脚本，但保留服务器现场的 `pms-operations.json`，不得用示例配置覆盖。
8. 按原服务管理方式启动后端；仅在确认 Nginx 配置和进程后执行必要的重载。

不得把开发机数据库、测试账号配置或 `.env.kingdee.example` 当作服务器真实配置。

## 部署后验收

按顺序验证：

1. `/api/health` 返回 `{"status":"ok"}`。
2. PMS 直连页面可以打开并正常登录。
3. OA 菜单进入 PMS，SSO 回调和用户映射正常。
4. 项目档案、项目进度、系统管理页面可以读取，权限与按钮状态正确。
5. 项目档案文本、选择、日期字段在 Windows 直连和 OA 嵌入环境无双框、文字移位或尺寸跳动。
6. 先做不写业务数据的金蝶连接查询。连接工具自身 read_only=true 不代表服务写入开关。核对并恢复现场已批准的服务写入状态；如需额外样本保存，另明确样本及范围，不擅自批量同步。
7. 操作日志没有异常写入或敏感内容。
8. 在已批准窗口安装 `ops/windows` 计划任务后，验证开机启动、五分钟健康检查和每日日志轮转；首版保持 `autoRestart=false`。

任何关键验收失败，都停止继续扩大使用范围，并保留现场日志和版本信息。

## 回退

1. 停止本次新启动的 PMS 后端进程。
2. 恢复部署前完整备份的后端程序和前端生产目录。
3. 恢复原 Nginx 与服务启动配置；受保护配置和数据库仅在确认本次确实改动后按对应备份恢复。
4. 按原方式启动服务，重新验证 `/api/health`、PMS 直连和 OA SSO。
5. 记录失败环节、当前版本、回退版本和验证结果。

回退程序版本不等于撤销已经成功写入的业务数据。发布验证默认仅查询；若此前已有正常业务写入，程序回退不会撤销这些结果。
