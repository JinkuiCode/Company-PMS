# 采购进度查询 V2 样稿

## 发给业务同事

- 独立文件：`release/采购进度查询-V2-业务确认样稿.html`，约7.5MB。直接使用 Edge 或 Chrome 打开，不需要 PMS 服务、公司网络或额外资源文件。
- 全部为模拟数据，不包含账号密码和真实业务记录。查询方案仅保存在各自浏览器中，不会同步给其他人。
- 已使用 Edge 断网模式通过本地文件完整交互测试，未发出 HTTP/HTTPS 或业务 API 请求。
- 当前停留在业务确认阶段，等待同事反馈后再继续正式报表实施。

- 入口：`http://127.0.0.1:5174/prototypes/purchase-progress.html`，依赖现有本地前端开发服务。
- 范围：独立前端样稿，没有加入正式菜单、路由和构建入口；未连接业务 API、金蝶、数据库或服务器。全部单据、供应商和数量均为模拟数据。
- 实现：复用 PMS 主题、内置字体、标准列表容器、统一文本和选择控件；主表按申请明细组织，订单和入库分别汇总，通过右侧只读抽屉展示关联链路。
- 可操作：模糊搜索、项目/供应商筛选、进度筛选、列显示设置、分页、模拟 CSV 导出，以及保存和恢复本机查询方案。查询方案同时保存筛选、列显示和每页数量，使用独立样稿存储键，不改正式列表偏好。
- 列设置可显示申请单号及行号、物料编码和规格、各单据状态；默认主表保留常用摘要，以横向滚动访问其余列。
- 示例：第一条气动隔膜阀申请 100 只，9月12/14/17日分别下单40/35/25；第一条订单9月15/18日入库20/15，第二条9月19日入库10，第三条未入库。汇总下单100、入库45。加热器申请20，分两批下单8/4，第一批分两次入库2/4，展示部分下单且部分入库。
- 明细：桌面抽屉约760px，顶部只保留申请单号/行号、物料名称和申请数量单位；以下为关联订单与关联入库两张平铺表。点击订单行或用键盘激活订单号，筛选该订单行的入库记录；“查看全部”恢复所有记录，切换申请自动清除订单筛选。删除数量卡片、重复项目信息和逐单卡片。
- 口径边界：样稿所有数量使用同一单位且不含退货、关闭、作废及无源单数据，未入库数量暂按申请减入库展示。正式计算口径及金蝶关联字段须在实施阶段依据真实样本确认，不能将样稿差额公式直接当成最终规则。
- 待确认：主表分组和默认列、进度筛选、明细抽屉宽度与订单/入库层级。正式报表底座、权限、数据接入及 Metabase 接入均未实施。
- 验证：Edge 样稿行为测试覆盖拆单/分批入库、未下单空状态、搜索、查询方案持久化、列设置及 1600/1366/390 宽度；业务 API 请求数为 0。现有样式、标准列表和系统 UI 契约及前端构建通过。
