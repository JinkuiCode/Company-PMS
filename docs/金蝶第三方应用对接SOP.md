## 1. 方案与账号占用

PMS 在后台使用“第三方应用授权＋官方 SDK 请求签名”调用金蝶。所需信息是应用 ID、应用密钥、账套 ID 和一个指定金蝶用户，不需要 PMS 保存该用户的个人登录密码。

本实现不是标准 OAuth AccessToken 流程，也不能称为完全无 Session：官方 SDK 仍含 Cookie/Session 处理。是否占用许可证取决于金蝶实际授权规则，不由认证名称决定。

现场用户已确认：账号分配角色组后占用一个许可位置。因此，正式 PMS 对接只配置一个专用金蝶业务账号，应用只绑定该用户；不要为每位 PMS 使用者创建金蝶集成账号。测试及本次正式部署均暂时复用已有 I0001，未为对接另建用户。正式专用账号若为新建，按现场规则准备一个许可位置；不要为了腾许可而停用仍供员工使用的个人账号。

PMS 登录账号 ael 与金蝶执行账号 I0001 是两个系统的身份。PMS 操作日志记录实际 PMS 操作人；金蝶请求使用指定的集成用户。管理员只负责配置应用，不作为日常接口执行账号。

## 3. 建立第三方应用

1. 管理员登录目标账套，核对数据中心名称。
2. 打开 **系统管理 → 第三方系统登录授权**，先查找 PMS系统对接，已有记录应核对复用，避免重复创建。
3. 新增时填写应用名称 PMS系统对接。应用密钥由金蝶生成，不手工编造。
4. 点击 **获取应用ID**。本现场出现“第三方系统登录授权—手工配置”，按弹窗给出的官方应用市场入口办理。
5. 核对环境用途、账套、服务地址和企业信息。该过程会向金蝶应用市场提交环境及企业信息，由企业授权人员操作；测试选择测试环境，正式登记使用对应正式环境。不要借用其他账套的应用信息。
6. 将返回的完整应用信息填回弹窗，确认输入框实际已有内容，再点确认。不要截短 AppID；“复制成功”提示不能替代输入内容检查。
7. 打开 **指定用户登录**，双击用户单元格，使用选择按钮检索目标用户，勾选后确认“已选 1 行”，返回数据。本次测试与首轮正式部署均获准使用 I0001，后续再切换批准的专用用户名。保持“允许全部用户登录”不勾选。
8. 保存并重新打开记录，确认应用启用、AppID 保留、指定用户仅一位。页面上的“测试用户”字段不等于指定授权名单。
9. 需要取得密钥时，点击查看密钥，由管理员本人完成二次认证。现场版本的完整密钥显示在“当前密钥为……”提示框，原字段仍为遮盖内容；不要把遮盖值写入配置。完整密钥只进入受保护配置，不回显、截图或记录原文。

“链接有效时间”“生成测试链接”是单点登录链接设置，不能据此判断 WebAPI 密钥有效期。浏览器单点登录成功也不能替代 API 验收。IP 白名单按实际后端出口地址另行核对，不随本流程默认改动。

## 4. 配置与启动 PMS

配置文件为实际运行后端目录下的 `backend/.env.local`，模板见 [配置模板](../backend/.env.kingdee.example)。系统环境变量优先于文件，修改前应检查是否存在旧环境变量覆盖。

| 配置项 | 设置要求 |
|---|---|
| K3_AUTH_MODE | app |
| K3_READ_ONLY | 初始验证及暂停同步设 true；正式日常同步经批准后设 false，本现场当前为 false |
| K3_URL | 对应金蝶服务地址 |
| K3_ACCT_ID | 对应目标账套的 API ID |
| K3_USERNAME | 该应用唯一指定的业务用户 |
| K3_APP_ID | 该账套应用的完整 ID |
| K3_APP_SECRET | 对应完整密钥，仅保存在受保护配置 |
| K3_LCID | 简体中文 2052 |
| K3_ORG_NUM | 本次为 0；指定业务组织时先核对接口要求 |
| K3_PASSWORD | app 模式不使用；仅显式密码方案回退时才需要 |

macOS/Linux 文件权限为 600；Windows ACL 只授予运行账号和授权管理员必要权限。安装依赖时必须使用实际后端解释器；官方 SDK wheel 固定在 backend/vendor，来源、版本及校验值见 [SDK 说明](../backend/vendor/README.md)。不在排错时随意升级 SDK。部署前检查 requests、urllib3 等 SDK 依赖；本次服务器无法解析 PyPI，采用开发机下载匹配 Windows Python 3.13 的 wheel、校验 SHA256 后内网离线安装。保留服务器已有 idna/certifi；新增 requests 2.34.2、urllib3 2.7.0、charset-normalizer 3.5.1。

配置变更后重启目标 PMS 后端，并核对实际源目录、版本、端口与数据库。**启动成功、命令行测试成功、运行中的 PMS 已切换，是三个不同结论。** 不确认运行来源时，不重启或覆盖其他任务的服务。

## 5. 字段映射和同步规则

| PMS 来源 | 金蝶字段 | 规则 |
|---|---|---|
| 固定销售项目类别 xsxm | FId.FNumber | 仅同步这个类别 |
| 项目编号 project_code | FNumber | 用于匹配目标记录；当前更新路径不修改编号 |
| 项目名称 project_name | FDataValue | 新建及更新均传入 |
| 固定“PMS 项目档案同步” | FDescription | 新建及更新均传入 |
| 金蝶查询得到的内码 | FEntryID | 更新时使用；不能人工猜测 |

客户、负责人、产品类别、设备系列、序列号、计划日期目前不传金蝶。扩大映射前需要明确目标字段及业务规则。

查询同时限定类别和项目编号；引号按字面量转义。未找到才进入新建，找到一条进入更新，发现多条立即停止。查询业务错误即使 HTTP 为 200，也不能当作“不存在”。保存以 Result.ResponseStatus.IsSuccess 为保存成功依据；只有随后回查到“已审核”（FDocumentStatus=C），PMS 才记录同步成功。

保存后自动执行以下流程：创建/暂存/重新审核状态（A/Z/D）先提交；审核中（B）执行审核；已审核（C）直接核对资料，不重复提交审核。每一步均检查业务返回，并重新核对类别、编号、名称、内码和状态。保存返回内码必须与后续查询一致。未知状态、重复记录或内码漂移立即停止。

已审核资料使用正常 Save 更新，本现场测试账套验证更新后仍为 C；不自动反审核。其他账套或字段若要求反审核，应停止并另行确定业务处理。指定集成用户须具备目标资料的查询、新增/修改、提交和审核权限；不要通过扩大为全权账号处理失败。

保存、提交或审核结果超时或格式异常时，不能断定未执行，也不能自动重试；必须先回查金蝶实际数据。代码回退不能撤销已经发生的金蝶业务写入。

## 6. 验收步骤

### 6.1 自动回归

在含本批修复的 backend 目录，使用已配置依赖的 Python 执行：

```text
python tests/kingdee_auto_audit_contract.py
python tests/kingdee_query_scope_contract.py
python tests/kingdee_app_auth_contract.py
python tests/project_archive_lifecycle_contract.py
python tests/project_archive_lifecycle_concurrency_contract.py
python tests/operation_log_contract.py
```

涉及额外配置初始化、权限或字段变更时，补充对应配置、RBAC、字段契约。测试必须逐项退出 0。内存测试通过只证明代码行为，不能代替真实金蝶授权及保存验收。

本批在修复工作树 backend 目录使用 `PYTHONPATH=. /Users/jin/Code/PMS/backend/.venv311/bin/python tests/对应测试.py` 验证；生产使用实际 Python 3.13 解释器。应按依赖已安装的解释器运行，不混用缺少依赖的环境。

### 6.2 只读连接

1. 确认实际进程使用正确账套、应用、指定用户，K3_READ_ONLY=true。
2. 在该配置对应环境运行 `python scripts/check_kingdee_connection.py`。通过标准为退出 0、success=true，认证模式及账套/用户正确。该工具只做查询，其输出的 read_only=true 表示工具自身不保存，不能单凭此值推断服务进程的开关。
3. 需要时用 `--project-code` 查询一个已核对编号；未找到不代表拥有新增权限。
4. 用户登录 PMS，从已认证入口调用 POST /api/erp/test。应通过 project:archive:sync 权限校验，HTTP 200 且 success=true；不开放匿名接口、不绕过权限。

当前业务界面没有独立的连接测试按钮。本次使用同源临时验收页，使用当前登录身份调用原受保护接口；验收后页面与文件已清理。日常实施人员应使用受控验收工具，不从浏览器导出令牌到文档或工单。

### 6.3 新建与更新

1. 确定唯一测试编号、名称、允许新建/更新的范围及样本保留方式。先只读检查本地 PMS 和目标金蝶类别，确认不会覆盖业务记录。
2. 记录配置与运行版本，检查没有在途同步。在批准窗口使用受控的样本范围与超时限制，仅操作已批准样本；本次生产方式见 9.1。不要把全局开放写入当成单样本验收的必要条件。
3. 在 PMS 新增项目档案并保存，点击该记录“同步”；在金蝶只读回查类别、编号、名称、内码及已审核状态 C。
4. 仅修改批准的字段，使用“保存并同步 ERP”；回查内码未变、目标仍唯一、字段值正确、审核状态为 C。
5. 核对 PMS 显示已同步，同步日志包含 create/update 成功，统一操作日志包含创建、修改和同步操作人。
6. 仅临时样本验收且尚未批准常态同步时，验收结束退出临时入口，以 K3_READ_ONLY=true 的普通后端启动，确认无遗留验收进程、实际端口归属及健康状态，并验证只读拒绝发生在联网前。样本按批准方式保留或处理，不得擅自删除。

## 7. 正式账套及专用账号切换

正式上线是独立窗口，不能把测试通过直接当作正式启用。

1. 用户确认正式账套 API ID、专用用户名、组织和业务权限、上线时间及正式验收样本。按现场规则核对该专用用户占用的许可位置。
2. 暂停 PMS 同步，检查在途及结果不确定的请求；备份当前正式程序、配置和数据库，并记录实际运行版本。
3. 在正式账套建立或核对正式 PMS 应用。不能直接沿用测试账套 AppID/密钥，也不能假设复制账套后应用授权可跨账套使用。
4. 在维护窗口将该应用的唯一指定用户替换为专用账号并保存；不勾选全部用户。需要回退时恢复原唯一指定用户，不删除个人账号本身。
5. 对照核对整组配置：账套、AppID、密钥、用户及组织。先保持只读，部署经批准代码并重启目标服务。
6. 依次验证健康、PMS 正常登录/OA 原入口、授权连接测试、必要的只读资料查询。确认许可和现有员工使用未受异常影响。
7. 按批准的正式样本短时验证业务写入，通过后再按正式运行安排开启同步。未通过则停止，不以临时全权限授权代替定位。
8. 删除 PMS 配置中不再使用的个人密码等旧集成凭据，但不删除或禁用个人金蝶账号。记录切换人、时间、目标用户和验收结果。

替换金蝶用户后，历史金蝶资料创建人不会自动变化。PMS 的用户权限与金蝶集成账号的权限分别管理。

## 8. 密钥轮换、故障处理和回退

轮换：暂停同步，由管理员在正确账套的 PMS 应用中完成重置、二次认证及保存；通过安全渠道更新受保护配置，重启并做只读验收。新密钥成功后，用独立连接确认旧密钥失效。已吊销密钥不能作为回退凭据。

| 现象 | 处理 |
|---|---|
| PMS 提示用户名或密码错误 | 请求到达 PMS 后端但登录校验失败；区分 PMS 登录账号与金蝶账号 |
| 点击登录没有提示 | 检查请求响应及页面错误反馈，不能直接认定密码错误 |
| 文件改了但行为不变 | 检查运行目录、环境变量覆盖及进程是否重启 |
| 认证失败 | 核对账套、完整 AppID、真实密钥、应用状态和指定用户名单 |
| 查询失败 | 检查组织与资料查询权限；停止同步，不继续新增 |
| 查到重复编号 | 只在目标类别中人工核对，不自动选择第一条或删除重复项 |
| 查询成功但保存拒绝 | 核对新增/修改权限及字段校验；查询权不等于保存权 |
| 网络、时间戳或签名异常 | 检查网络可达、系统时钟及配套 SDK/应用信息 |
| 保存后提交/审核失败 | PMS 记录失败；检查该步骤的业务报错和真实状态，不能把已保存当成已同步 |
| 提示金蝶单据被占用 | 请在金蝶端退出当前单据后，再次点击 PMS 的“同步”；若提示其他占用人，联系该用户正常退出。先保留人工未保存内容，不强制解锁。当前正式写入已启用，按正常业务流程重试 |
| 保存结果不确定 | 先只读回查，确认实际是否落库，不直接再次点击同步 |

优先回退到已验证的应用配置及程序版本。回退整组目标配置，不能混用不同账套的用户、AppID 和密钥；先恢复只读再核验。

确需回退密码方案时，须使用经批准的有效账号，明确设置 K3_AUTH_MODE=password，恢复配套账套/用户/受保护密码并重启只读验证。应用认证失败不会自动降级。不要调用用户级全局注销影响个人其他登录。

程序、配置或数据库回退都不自动撤销金蝶已保存的数据；数据修正必须单独核对受影响记录与处理方式。
