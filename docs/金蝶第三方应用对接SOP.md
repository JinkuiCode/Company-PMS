## 1. 适用范围与通俗说明

本流程适用于企业内网 PMS 后台对接金蝶云星空企业版。现场已查看版本为 `9.1.0.20250807`；其他版本菜单名称可能不同。

原来 PMS 拿用户密码登录金蝶；现在给 PMS 单独登记一个“应用”，由应用 ID、应用密钥和指定金蝶用户共同完成认证。应用密钥可独立维护，换集成账号不用改业务代码。

本次实现使用金蝶官方 Python SDK 生成请求签名。不要将它写成“标准 OAuth AccessToken”或“完全没有 Session”：官方 SDK 内含 Cookie/Session 处理。本方案也不保证免许可证。按现场管理方确认的命名用户规则，测试使用已有 I0001；正式上线使用一个专用账号，许可数量以其角色组分配为准。

管理员负责登记应用；PMS 运行时使用绑定的业务账号，不使用 Administrator。

## 3. 在金蝶建立第三方应用

1. 用管理员身份进入正确账套，核对页面顶部的数据中心名称。
2. 进入 **系统管理 → 第三方系统登录授权**。先查找 `PMS系统对接`，已存在时核对记录，避免重复创建。
3. 点 **新增**，应用名称填 `PMS系统对接`。应用密钥由系统生成；不要截图或复制到普通文档。
4. 点 **获取应用ID**。本现场弹出“第三方系统登录授权-手工配置”，要求到金蝶应用市场生成应用信息。
5. 按该弹窗提供的官方地址进入金蝶应用市场，核对当前环境类型、环境标识、账套和服务地址。此链接会向 `appmarket.kingdee.com` 传送产品唯一码、内部服务地址和账套 ID，提交表单还包含选择的企业信息；按企业数据传输管理要求取得授权后再继续。若需要登录，由有权限的管理员完成。本次企业为江苏亚电科技股份有限公司（已认证），用途应选择“测试环境”。不要使用其他账套的应用信息。
6. 将应用市场返回的“应用信息”完整填回弹窗，确认输入框确实已有内容后点 **确认**。须核对导入后的完整应用 ID；不能手工编造、截短或借用“导入”等其他应用的 ID。现场自动化曾遇到页面提示复制成功但浏览器剪贴板为空，不能仅凭提示判定填入成功；空值会报“请填写正确的应用信息”。
7. 在 **指定用户登录** 页签，双击空白用户单元格，点选择按钮打开用户列表；按“用户名称”输入 `I0001` 并回车，等待筛选完成。核对用户说明“金奎宇”，勾选该行，确认“已选 1 行”及右侧选中列表均为 I0001，再点 **返回数据**。只在单元格直接输入文本可能未绑定用户，保存会报“请维护允许登录用户信息，再保存”。上方“测试用户”字段不等于授权名单；保持“允许全部用户登录”不勾选。
8. 保存，返回列表查到 `PMS系统对接`，确认未禁用；重新打开检查应用 ID 和指定用户名单已保留。
9. 点 **查看密钥**。现场会提示该敏感操作写入上机操作日志；确认后弹出 **二次认证**，用户名 Administrator、认证方式“命名用户身份”，须管理员本人输入密码并点确定。密码不交给他人、不写入 SOP。读取完整应用密钥后仅存入受保护配置，不能把页面脱敏值当成可用密钥。**本版本现场确认：二次认证成功后，真实密钥在“当前密钥为……”提示框中，原应用密钥字段仍含遮盖字符，不能读取该字段用于配置。应在不回显页面全文、不截图、不记录原文的前提下，将提示框中的密钥直接送入受保护配置，再关闭提示框。**不要点击“重置密钥”或改动其他应用。生成集成密钥不是本实现的必需步骤，本次尚未使用。

页面中“链接有效性”“链接有效时间”“生成测试链接”属于单点登录链接配置，不能据此推断 WebAPI 凭据有效期，也不能用浏览器 SSO 成功替代接口验收。IP 白名单如需开启，应先明确 PMS 后端实际出口 IP；本次不更改既有网络策略。

## 4. 配置 PMS

配置入口：`backend/.env.local`，模板：`backend/.env.kingdee.example`。部署系统环境变量优先于此文件；环境变量存在旧值时，修改文件不会覆盖它。

| 配置项 | 用途 | 本次填写方式 |
|---|---|---|
| K3_AUTH_MODE | 明确选择认证方案 | `app` |
| K3_READ_ONLY | 禁止 PMS 发送保存请求 | 代码默认 `true`；指定业务写入样本获准后才显式设为 `false` |
| K3_URL | 金蝶服务地址 | `http://10.10.1.248/k3cloud` |
| K3_ACCT_ID | API 账套 ID | 填已确认目标账套的 ID |
| K3_USERNAME | 已授权的集成用户 | 测试 `I0001` |
| K3_APP_ID | 完整应用 ID | 从该应用的实际授权信息取得 |
| K3_APP_SECRET | 应用密钥 | 仅写受保护配置，不写入本文 |
| K3_LCID | 语系 | 简体中文 `2052` |
| K3_ORG_NUM | 组织编码 | 默认 `0`；若业务指定组织，按金蝶组织编码设置 |
| K3_PASSWORD | 原密码认证回退凭据 | 应用模式不使用；不需要重新询问个人密码 |

## 6. 正式上线：替换专用账号

1. 准备一个有效的金蝶专用用户，给其所需组织/角色组及辅助资料查询、新增、修改权限。只分配业务需要的权限；许可按现场规则分配一个集成账号。
2. 暂停 PMS 同步，等待进行中请求完成，特别核对不确定状态。
3. 管理员在 `PMS系统对接` 的指定用户名单中加入新用户；先不要撤掉 I0001。
4. 修改受保护配置 `K3_USERNAME` 为新用户。应用仍为同一个时，AppID/AppSecret 通常保持原值；若实际重新建了应用，必须同时替换二者。
5. 重启后端，确认没有遗留的进程/环境变量继续使用旧用户，运行只读检查与指定样本验收。
6. 验收通过后，从该应用指定用户名单移除 I0001，并移除 PMS 保存的旧个人密码。不要删除或禁用个人账号本身。
7. 记录切换时间、操作者、应用、旧/新账号及结果。旧业务单据的创建人不会因为替换配置而自动改变。

若切换失败，在尚未移除旧用户时恢复 `K3_USERNAME=I0001` 并重启；已移除时由管理员恢复原指定授权后再验证。

## 7. 常见故障处理

| 现象 | 核对与处理 |
|---|---|
| 本地测试成功，真实认证失败 | 检查实际环境变量、目标账套、完整应用 ID、真实密钥、应用启用状态和指定用户名；不要只看“测试用户” |
| 只改配置后效果没变 | 检查部署进程使用的源目录、环境变量优先级和是否重启 |
| 查询拒绝 | 核对绑定用户的目标组织与辅助资料查询权限；本次同步会停止，不会继续新增 |
| 查询成功、保存拒绝 | 查询权不代表新增/修改权，检查字段校验及业务权限，不扩大到所有用户/全权限作为通用修复 |
| 签名/时间戳错误 | 确认系统时钟、完整 AppID、配套 AppSecret 和官方 SDK 版本；勿复制脱敏密钥 |
| 网络连接错误 | 确认后端能访问内网金蝶地址；此现象不证明账号或许可证不足 |
| 保存超时/结果不确定 | 先核查金蝶实际数据，禁止自动重试造成重复写入 |
| 更换用户后失败 | 新用户必须同时出现在应用指定名单并具备目标业务权限 |

密钥泄露或轮换由受权管理员处理：暂停同步，在该 PMS 应用中重置密钥，立即同步更新受保护配置并重启验证。不得重置其他应用；轮换后旧密钥不能作为回退凭据。

## 8. 回退原密码方案

1. 停止新同步并核对在途请求结果。
2. 在受保护配置中明确设置 `K3_AUTH_MODE=password`，恢复经核对的原账套、用户和密码配置。
3. 重启后端，运行只读检查；应显示 `auth_mode=password`。应用认证失败不会自动触发此回退。
4. 恢复业务前核对不确定状态和金蝶实际资料。本回退只切换认证，不回滚数据库或撤销已成功的业务保存。
5. 记录原因与结果；是否暂时禁用 PMS 应用由管理员按使用情况决定。不要调用用户级全局注销影响个人其他登录。
