# PMS 前端界面规范

## 三主题开发基线（2026-10-19）

用户已批准办公蓝、青绿、石墨三套浅色方案，以及档案试点、三张报表和其余页面的开发接入。本节是本批已确认的配色修订，优先于下文旧靛蓝配色描述；不代表正式环境已发布。

- 主题由 `frontend/src/theme-system/` 独立维护，实际 `App.vue` 每个文档仅挂载一个 Provider，页头引用共享切换入口。业务页面不复制主题值或第三方控件适配。
- 主操作采用当前主题实色；设置、重置、取消、引用等辅助操作采用克制白底、淡边及清晰文字，不再要求每种辅助按钮使用不同颜色。导出和成功反馈保留青绿，警告琥珀，危险红色；状态不只靠颜色表达。
- 展开态与收起态同属验收范围：查询下拉、多选、树、日期、分页、引用、抽屉、行内及表格编辑、悬停、键盘焦点、错误、禁用和只读均使用共享令牌。分页复用 `PmsSelectControl`，外层26px，其余已确认查询/编辑尺寸和内置字体不变。
- 进度统一引用 `progressAppearance`；不足50%红色，50%至未完成黄色，真实完成绿色。使用原始计数判定完成，不能因显示值四舍五入为100%变绿；0%不伪造填充。固定阶段色和异常语义色不随主题改变，不改业务计算。
- 偏好按来源环境及有效用户隔离，刷新、跨页签保持。公开说明页只读取无身份的外观提示，不为主题功能初始化登录状态，也不读取或传递认证凭据；身份/授权仍由原模块负责。存储不可用时当前选择仍可用并显示保存失败提示。
- OA自身布局与配色不在修改范围；PMS保持44px页头、64px折叠菜单、24px查询、32px编辑和原有表格密度。跨页面切换外观不得触发业务查询、丢弃草稿或重置列宽、排序、筛选、分页与选择。
- 迁移顺序保持独立模块、档案试点、报表、其他页面；适用技术验证及独立审查完成后另行交付。正式发布、主分支合并和推送仍需各自授权。

## 新增页面说明与单字段查询

每个新增功能页面须引用 `page-guide/PmsPageGuide.vue`，注册独立的页面键、操作说明和字段逻辑，复用搜索、分组与新页签打开。说明模块独立维护，不在业务页面复制实现；说明须与当前角色范围、写入/导出和通知规则一致。说明独立页不循环添加说明入口。既有页面分批接入，首期档案、三报表及问题提报。

查询方案一个条件只匹配一个字段，不创建综合搜索伪字段。需要多个字段时由用户添加独立条件，保持现有组合逻辑。已取消的旧字段保留原方案记录并阻止执行，用户在方案设置确认重配后再查询，不将历史OR含义默改为AND。

## 目标

PMS 面向企业内部高频使用，界面以项目档案和项目进度为基准：浅色、紧凑、清晰、可扫描。页面应优先提高信息辨识度和操作效率，不使用与业务无关的装饰。

## 字体与字号

- 中文正文统一使用项目内置 `Noto Sans SC`，入口为 `frontend/src/main.ts`，全局变量为 `--pms-font`。CSS 引用名称必须与内置字体声明一致，当前为 `Noto Sans SC Variable`，不能省略 `Variable` 后回退到系统字体。
- Element Plus 与 AG Grid 必须继承 `--pms-font`，页面不得单独声明系统字体栈。
- 常规正文和表格数据使用 `13px`，辅助信息和表头使用 `12px`，分区标题使用 `14px`，页面重点标题使用 `16px` 或 `18px`。
- 编号、字段编码等技术值使用 `.pms-code`，数字统计应使用等宽数字。

## 页面骨架

- 标准业务列表使用 `PmsDataList.vue`、`PmsListFilters.vue` 和 `useListFilters.ts`。
- 系统管理页根节点使用 `.pms-system-page`。
- 独立内容区使用 `.pms-surface-section`；双栏页面使用 `.pms-split-page`。
- 分区头部使用 `.pms-section-header`，标题和辅助信息分别使用 `.pms-section-title`、`.pms-section-meta`。
- 页面内不重复创建大面积卡片，也不使用重阴影和大圆角。
- 2026-10-08已确认OA紧凑工作区及验收修订：PMS页头44px，外边距6px，面板内距8px，登录后菜单默认收起为64px图标栏，悬停展示下级菜单，手动展开184px。不得完全移除侧栏；尺寸复用共享主题令牌，OA外层不在PMS调整范围内。

## 表格与筛选

- Element Plus 表格统一增加 `.pms-dense-table`，AG Grid 使用 `.pms-ag-grid`。
- 所有单据列表的字段名水平居中，包含操作列、冻结列、普通列和分组标题；正文仍按语义对齐，不随表头改成全部居中。正文13px、行高32px、单层表头30px、分组表头26px；多行管理信息允许自然增高，不裁切内容。
- 查询区通过`.pms-query-density`复用表单控件：高度24px、字号12px、行高18px、间距6px、上下内距4px；按钮圆角4px、水平内距8px。方案选择、保存、查询、重置、添加条件、导出与列设置同高，多选标签必须完整位于框内。查询配置不得传播到普通表单及行内编辑。
- 2026-10-12已确认共享查询紧凑宽度：字段96px、运算符68px、值132px、移除18px、间距4px，普通组326px；日期/数字区间组434px（值区域240px）。方案选择132px；条件组不随剩余空间横向拉伸，窄屏自动换行并限制到可用宽度，不能撑出页面或隐藏功能。设置抽屉和普通编辑仍保持32px标准。
- 分页控件26px，顶距和内距4px；工具栏与分页按内容占高，表格占据剩余可用高度并内部滚动。
- 列多时必须提供可见横向滚动条；分页紧邻表格，不放到页面最底部。

## 控件与状态

- 所有功能按钮均须带语义色，同类功能跨页面使用同色，取自共享主题令牌，不以页面或开发者喜好随意改变。主操作可实色，辅助操作使用淡色填充/边框或带色文字，避免满屏重色；禁用、焦点、悬停及文字对比仍遵循共享组件标准，不能仅靠颜色传达功能。
- 2026-10-11列表工具栏样稿获批后的统一映射：查询/新建/保存方案使用靛蓝实色 `primary`；方案设置、重置、取消、添加条件、引用、列设置复用白底淡边的 `.pms-button-auxiliary`；导出使用淡青绿 `.pms-button-export`；删除真实业务数据仍使用 `danger`。移除查询条件不是删除业务数据，使用无外框叉号 `.pms-button-dismiss`。色值集中于共享主题，不在业务页覆盖第三方内部结构。此批只迁移列表查询相关操作，不改变普通业务表单的语义配色。
- 同一行按钮、字段框保持等高：列表24px，方案名称和弹窗搜索32px。引用多选摘要显示前三项（允许省略号）及独立总条数，悬停可看完整选择；值区域 `min-width:0` 且不得溢出。
- 有新增操作或视图切换时，业务行左侧放主操作，右侧放导出/任务/列设置；没有业务操作时不创建空业务行，辅助入口放在共享查询方案栏的 `after` 插槽右侧。查询方案选择、方案设置、查询、重置、添加条件同一栏。档案初始化入口置于最右侧“初始化工具”菜单，不排在新增之前。
- 业务单据和报表提供导出，系统管理不提供。档案及项目/任务分别通过 `project:archive:export`、`project:list:export` 独立授权，仍须同时具有查看权限和数据范围；报表保留原独立导出权限。导出采用已提交表头条件、当前可见列和排序，导出全部匹配记录而非当前页，不包含未提交草稿或仅当前页的漏斗条件。
- 业务单据导出使用主键上界及稳定游标扫描，避免并发新增/删除引发分页偏移，再按列表排序输出。该扫描不代表数据库一致时点快照；导出期间修改的记录仍可能读取到变化后的值。下载成功、异常及取消均清理临时文件。
- “档案初始化模式”参数 `archive.initialization_enabled` 默认开启。正式上线关闭后，期初导入与分配产品线入口隐藏，后端也拒绝相关操作；不影响常规档案维护，已导入批次的回退仍须原权限和业务校验。
- 勾选框属于选择控件，不套用功能按钮的额外外框。鼠标勾选不显示包围整个控件的焦点圈，键盘操作保留可辨识焦点；不能简单删除所有焦点反馈。2026-10-11已在共享引用弹窗命名空间及档案试点落地此规则，正式全局表单令牌与其他控件保持不变。
- 状态统一使用 `.pms-status`、状态点及语义色，不在页面内另写一套胶囊标签。
- 图标优先使用 Element Plus 图标。数据库动态菜单使用的图标名称，必须同步注册到 `AppLayout.vue` 的 `iconMap`。
- 禁止使用 emoji 充当业务图标。

## 标准页面说明

- 正式说明入口为 `frontend/src/page-guide/PmsPageGuide.vue`，业务页只声明已注册的page键；内容统一维护在 `registry.ts`，不能在页面复制说明弹窗或引用样稿数据。已接入档案、三张报表及问题提报，采购总/明细共用一份说明；所有新增功能页面必须接入。
- 采用2026-10-12已确认B方案：工具栏列设置后24px“说明”按钮、居中弹窗、操作说明/字段逻辑页签、分组目录与搜索。内容使用独立滚动区域；标题与关闭按钮始终可见；支持键盘焦点、Esc关闭和返回触发按钮。
- 说明弹窗右上角统一提供24px蓝色“新页签打开”导航入口。独立页为 `/page-guide/archive|purchase|inventory|stock|feedback`，复用 `PmsPageGuideContent.vue` 和同一说明目录，不带业务列表或侧栏；通过URL片段保留当前说明类型、分组及搜索词，不传登录凭据或业务查询条件。2026-10-12批准前四项，2026-10-13批准问题提报接入：仅这些精确路径的纯静态说明免登录阅读，不请求认证或业务接口，不写入登录凭据；业务页面与接口仍沿用原登录及权限校验，禁止以路径前缀开放其他页面。新页签使用PMS自身来源，链接设置 `noopener noreferrer`；不操作OA父级，原数据页保持不变。
- 弹窗宽度不超过900px/94vw，高度限制在当前窗口；OA嵌入时只在PMS iframe内展示，不访问或修改父级OA页面、SSO或授权。窄/矮窗口需要验证正文滚动、按钮可达及无横向溢出；模拟iframe通过不代表正式OA已验收。
- 说明模块只读，无数据加载和写操作；字段逻辑应与列表、查询和导出同口径，变化时同步维护说明和测试。后续业务页逐批接入，禁止自动生成未经核实的业务规则。
- 报表公开列取消项目名称，默认产品线首列；即时库存只显示产品线，不另展示组织。内部组织ID及权限范围仍保留。旧列偏好通过 `report-identity-layout.ts` 一次迁移，清理失效列并保留列宽等个人设置，新版保存后尊重个人隐藏和排序。项目档案及引用弹窗继续保留名称展示/搜索。

## 统一表单系统

- 业务页面必须从 `@/form-system` 导入基础字段组件，不得直接使用 Element Plus 的 input、select、date、number、textarea、tree-select、switch 或 checkbox。
- 普通表单使用 `PmsFormField`，抽屉行内编辑使用 `PmsInlineField`，AG Grid 编辑使用 `PMS_AG_GRID_FORM_CLASS` 和 `mergePmsAgCellClass()`。
- 业务页面不得覆盖 Element Plus 控件内部 DOM 类名；第三方兼容修复只能放在 `form-system/form-tokens.css`。
- 新增字段必须同时验证默认、悬停、编辑、焦点、错误、禁用和只读状态。

### 新增和编辑布局（用户 B）

- 2026-09-18确认“参数 A + 用户 B”，2026-10-08确认紧凑尺寸。新增/编辑使用`form-system/components/PmsFormDrawer.vue`：460px抽屉、98px标签列、8px标签/控件间距、字段行上下5px；普通输入32px，头部12px/16px、内容0/16px/12px、底部8px/16px。窄屏限制到可用宽度，详情行内编辑和表格单元格编辑仍保留原交互及32px控件标准。
- 抽屉头部只放标题、必要的来源操作和关闭；内容区独立滚动；底部固定取消、创建/保存，危险或独立动作放左侧。未保存关闭需确认，保存失败不丢草稿。
- 本批用户管理先落地并验收，部门、角色、枚举与业务新增表单随后分批迁移。不得把原有表格单元格编辑或详情行内编辑一并改成这种表单。
- 参数设置使用 A 方案全宽密集表格；敏感值仅显示已设置/未设置，展开行输入新值，使用版本号防止覆盖他人修改。

## 颜色与实现约束

- 颜色、边框、圆角、字号和阴影统一取自 `frontend/src/styles/pms-theme.css`。
- 页面局部样式不得重新使用 Element Plus 旧默认色（如 `#409EFF`、`#303133`）或复制新的字体声明。
- 新增页面先复用全局类和现有组件；只有业务特有布局才增加局部样式。
- 修改有效菜单页面后运行 `frontend/tests/system-ui-consistency-contract.test.mjs` 和生产构建。

## 列表查询与分页一致性

- 统一查询模块入口为 `frontend/src/query-system/`。正式列表使用 `PmsQueryWorkspace.vue`，条件行使用 `PmsQueryConditionRow.vue`，方案状态使用 `workspace.ts`，类型、运算符与校验使用 `core.ts`。项目档案、三个报表及其他列表共享同一模块，不在业务页另写方案抽屉、运算符目录或固定过滤控件。业务页仅声明字段目录、默认条件、引用 provider、已提交查询接口和布局偏好；报表和系统数据通过 `report-adapter.ts` / `system-adapter.ts` 适配自身数据源。
- 默认与临时条件均显示“字段名 / 条件 / 值”。方案选择、方案设置、查询、重置、添加条件在同一工具栏；保存只在方案设置中提供。设置中的方案名称、默认方案、新建方案放在同一行，可配置默认展示、运算符、默认值及顺序，临时条件带入设置但取消不保存。所有条件控件使用24px查询尺寸，设置抽屉使用32px表单尺寸。
- 方案使用真实登录用户ID和列表标识隔离，浏览器内每用户每列表最多一个默认方案。重新选择同一或其他方案、重置时恢复已保存条件并清除列筛选和临时条件，不自动查询。方案保存后仅影响本人；旧浏览器方案记录保留，转换时维持旧条件版本，不以删除旧记录实现迁移。
- 方案含已取消字段时，公共模块只在内存中整理并提示，阻止查询；需用户在方案设置确认并保存后才能继续查询。确认前保留原存储，不静默删除条件并扩大查询范围。
- 列筛选使用 `PmsQueryColumnHeader.vue`、`column-grid.ts`、`column-filters.ts`；服务端分页复用 `page-column-filter.ts`，客户端分页复用 `system-adapter.ts` 的 `pageRows`。先应用表头查询并分页，再对当前页快照本地过滤；候选排除自身列条件但保留其他列条件，禁止为漏斗读取跨页或调用全结果候选接口。AG Grid通过 `decorateQueryColumns` 接入，Element表格使用共享header slot和同一context。尚未查询或正在加载的业务列表通过context.ready关闭漏斗读取。翻页、条数变更、重新查询、重选方案及刷新页数据时清除漏斗；筛选列的表头和整列正文采用共享淡色背景，不增加结果筛选横条。
- 所有分页选择统一引用 `PAGE_SIZE_OPTIONS`：15、20、50、100、200、300、500，默认50；列表和实际分页引用接口接受最大500，方案恢复也使用同一目录。无分页页面的当前页即当前展示集合。列筛选不改变总条数、分页位置、汇总统计及后台导出范围。
- 列筛选弹窗与主工具栏复用24px尺寸和全局令牌：查询靛蓝、应用淡青绿、排序/辅助操作白底淡靛蓝、取消/清除琥珀、关闭无外框叉号；不单独硬编码多色重填充。
- 列筛选弹窗全页最多打开一个，统一由 `column-popup.ts` 管理；点击另一漏斗、同列标题或弹窗外部即关闭，OA嵌入窗口失去焦点时也关闭，不访问父级页面。关闭和卸载时销毁弹窗内容、移除外部点击/焦点监听、释放草稿并使旧候选响应失效；未应用的修改不生效，已应用筛选保持。内部下拉和日历挂载到所属面板，引用弹窗内的下拉挂载到所属引用区域，不能误关外层漏斗。
- 顶端查询条件在后端计数与分页前应用；漏斗只在本地已加载页应用，不传入后端查询、聚合或导出。下钻只携带兼容的基础查询条件与所选项目/组织范围，不把总表聚合字段或本页漏斗当作明细查询字段。正文只读/禁用不影响查询和列筛选权限。
- 文本提供包含/不包含/等于/不等于/左包含/右包含/为空/不为空；枚举提供等于/不等于/属于/不属于/为空/不为空；数字和日期提供比较、闭区间及空值操作。多个条件同时满足，多选内部任一值满足。空值操作隐藏输入；数字0有效；区间必须完整且有序。多选采用官方 small 配置，标签完整位于24px框内。
- 引用字段通过 `QueryField.reference` 声明来源 provider、稳定键与键类型，复用 `PmsQueryReference.vue`；项目编码/名称共用档案ID，不能用名称或行号代替身份。枚举自动以稳定存储值提供引用，同时支持按显示名字符过滤。档案 provider 复用原列表接口，候选和最终结果在每次请求校验既有页面权限、人员/部门及产品线范围；应用前复核所选记录仍可用，失效时提示重新选择，不静默移除限制。
- 产品线引用使用共享 `display: 'name'` 模式：候选与已选列表、勾选标签、摘要和提示均隐藏编码，仅显示配置的名称；搜索与Excel批量粘贴按名称匹配，加载或失效时不回退显示编号。后台保存、精准筛选及权限仍使用原稳定编号，不改接口取值或授权。其他档案引用保留各自编码/名称展示。
- 引用弹窗搜索为草稿，查询/回车才更新候选；不同搜索、分页和重置保留累计已选，下方独立显示已选明细并支持移除/清空。确认回填，取消保持原条件。候选失败、正在加载或已选不可用时禁止确认，过期异步响应不得覆盖当前结果。
- Excel 批量粘贴只处理用户主动输入的一列文本，不自动读取剪贴板；按行去空白/空行/重复，保留前导零，编码或名称精准匹配，输出未匹配和多候选提示，不自动勾选。多列制表符输入明确拒绝且保留上一成功结果。单次最多1000项，每项最多256字符，按100项及编码长度预算拆分读取，不能静默截断；最终SQL参数预算包含数据范围条件、显示标签及分页余量，超限提示拆分查询。所有引用型条件统一复用该行为。
- 条件面板只修改草稿，应用才查询并回第一页；取消、外部点击或关闭不得改已应用条件。弹层打开后移入焦点，关闭回到触发按钮，日历/下拉先处理自身Esc；错误关联到对应控件。已选择的历史人员值不能因离开当前结果页而失效。
- 新条件使用 `schemaVersion=2`，无版本旧条件按版本1保留旧空值及日期语义。后端使用类型白名单和绑定参数，在分页之前执行；文本通配字符（包含SQL Server方括号）按字面匹配。前端筛选不代替数据权限校验。
- 查询方案保存默认展示条件、每页条数和列偏好，不保存结果列筛选。加载先校验，失效字段提示且不扩大查询。`PmsQueryWorkspace entry-mode="document"`用于单据和管理列表：进入时等待个人默认方案、字段和数据依赖就绪，自动执行一次；重新进入重新读取。`entry-mode="report"`用于报表：默认待查询，仅读元数据，点击查询才取业务数据；已确认的采购下钻联动保留。重选/保存方案及修改条件仍须手动查询，条件保持草稿，不覆盖方案。默认必输值不足时待输入，禁止绕过校验。
- 查询必输条件统一由`PmsQueryConditionRow`读取字段`required`，在字段名前显示红色星号（共享`--pms-danger`），页面与方案设置一致；字段名称只保留业务名称，不附加“必填/必选/必输”。物料收发明细的物料和产品线必输、产品线多选、仓库只能选择等业务约束不变。

- 操作列尺寸标准（2026-10-13用户批准修订）：复用 `pmsActionColumn(count)`，单按钮64px、双按钮96px、三按钮136px，不以flex拉伸；`PMS_SINGLE_ACTION_COLUMN`及`PMS_ACTION_COLUMN`分别为单/双按钮快捷配置。单元格左右内边距6px、按钮40×24px、间距4px，左对齐、文字居中，12px/500；无操作内容的列表不新增空操作列。恢复个人列偏好强制规范化操作列，不覆盖其他列宽度、排序或筛选。尺寸使用`--pms-action-*`令牌，禁止页面另行覆盖。更多操作优先收进“更多”，不替代普通表单按钮规范。
- 项目进度行内入口统一称“编辑”，无编辑权限称“查看”，仍打开原详情抽屉；操作列使用稳定 colId，恢复个人列偏好时强制维持共享宽度及固定位置。
- 已分页页面统一使用 `frontend/src/config/listUi.ts` 的 `DEFAULT_PAGE_SIZE`，默认 50 条；不为未分页页面自动增加分页。
- 标准列表占满主内容区剩余高度，表格内部滚动，横向滚动条及分页固定在列表底部；禁止用固定 430px 上限或随数据行数撑高页面。
- AG Grid 与 Element Plus 表格的全文提示统一延迟 200ms，并允许长内容换行；通过全局配置维护，不在页面重复定义。
- 项目档案与项目进度操作列使用共享 `pms-actions-cell` / `pms-actions-header`，采用方案 A：不单独填充整列，继承普通行的正常/悬停/选中颜色。左侧冻结、中间滚动、右侧冻结区域以 1px 浅灰 `--pms-frozen-divider` 分隔，禁止用深色整列填充代替分隔。档案行内仅编辑（只读时查看）与同步，批量生命周期操作保留在工具栏。
- 列设置复用 `PmsListColumnPicker` 和 `PmsGridLayoutEditor`，以统一面板管理字段显隐、冻结、顺序和列宽，不分页签。已显示字段按左/中/右区域排列，未显示字段折叠后按业务分组列出。面板调整只修改草稿，底部固定恢复默认、取消和保存；保存后统一应用并按账号及浏览器保存，取消或关闭丢弃草稿。表头直接拖动仍自动保存。普通列受各列最小/最大宽度约束，默认 60-800px；勾选列和操作列固定，不参与自由排序及宽度调整。恢复默认先重置草稿中的显隐、冻结、顺序和宽度，保存后生效，不改变业务筛选条件。
- 分页按钮、每页条数、总数和表格内容必须来自同一个查询结果。服务端分页时不得再仅筛选/排序当前页。
- 恢复查询条件或已保存排序后再取页数据；条件变化回第一页，翻页保留条件，保存业务数据后按当前条件刷新并修正超出范围的页码。
- 客户端筛选仅适用于明确加载完整数据的列表，不得以固定 API 上限冒充完整结果；排序应先于分页。
- 列表加载应区分加载中、空结果和失败。并发请求必须防止旧响应覆盖新查询，翻页或更换查询时清理失效勾选。
- 普通文本列使用共享表格的宽度约束、单行省略及完整值提示，不允许跨列覆盖。编辑器和操作列仍遵循各自已有容器标准。

- 分隔线单一归属：表头由冻结表头容器绘制；数据行由 `.ag-cell-last-left-pinned` / `.ag-cell-first-right-pinned` 边界单元格绘制。数据容器和操作列不得再叠加边框；回归需同时比较左右表头、数据行的实际宽度和颜色。

## 列表与详情联动

- 所有新增主从页面：详情打开后，单击另一行同步展示该记录；未打开时单击仍只操作列表。勾选框及行内动作不得重复触发切换，点击字段名/空白不直接编辑字段。
- 有草稿时先提交当前编辑器到草稿，提供“保存后切换 / 放弃修改并切换 / 取消”三个明确选项；关闭提示等同取消。保存失败保留原详情、草稿和错误信息；放弃仅丢弃当前未保存内容，不发写请求。
- 复用 `frontend/src/utils/detailSwitch.ts` 和 `frontend/src/composables/confirmDetailSwitch.ts`。连续选择共享一次确认，仅最后有效选择应用；异步详情请求独立编号并核对记录ID。加载时显示加载状态，不允许编辑旧记录内容。
- 档案与进度为试点；回归使用 `frontend/tests/master-detail-browser.mjs`，覆盖切行、取消、保存失败、放弃及慢响应覆盖防护。

## 数字控件标准

- 加减按钮通过 `--pms-form-number-button-width` 控制宽度，紧凑 28px、标准 32px；有按钮、无按钮、右侧按钮模式分别计算输入内边距。
- 页面不得用普通文本输入框的内边距覆盖数字控件。回归同时检查输入区与按钮的几何边界、直接输入、加减、上下限及保存回显。

## 操作日志展示

- 日志详情使用后端 `diff_items`，字段中文名由字段目录、项目总表注册表和统一覆盖映射解析。
- 前端不得维护另一套业务字段中文名映射；原始字段编码仅作为次级技术信息展示。
- 枚举、布尔值、空值和嵌套字段应由后端格式化为业务可读值。

## 治理共享行为模块（2026-10-16档案试点）

- 新表单复用 `form-system/useFormSession.ts` 管理原值、草稿、验证前互斥和失败定位；字段规则、权限与并发版本仍由业务适配和后端负责，不合并审批/自动保存为巨型表单。
- 列表请求使用 `composables/usePageLoad.ts`：赋业务数据前拒绝迟到结果，防抖和离页立即废弃上一代请求；空结果、错误和重试保留原容器。
- 列偏好使用 `list-system/columnPreferences.ts`，按账号和页面隔离，固定业务列也需纳入保留范围；损坏或未知版本不静默覆盖，存储失败不得阻断业务查询。
- 字段元数据及结构化错误使用 `form-system/fieldMetadata.ts`；代码只读/隐藏上限不可被配置放宽，历史必填规则保留。异步错误定位结束前不能开放下一次提交或关闭。
- 本批仅档案试点，不代表既有页面全部迁移。调用方式和完整模块清单见 [共享模块接入索引](PMS-SHARED-MODULES.md)。
