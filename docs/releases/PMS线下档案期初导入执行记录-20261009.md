### 备份目录问题与纠正

独立升级凭据输入后，SQL实例默认备份路径属性未返回值，流程停在目录输入。助手尝试读取发布状态时，键盘命令误入该目录输入，导致备份ProgrammingError；没有继续停机、升级或导入。该错误是助手操作错误，未归责用户密码。当前数据库仍为2026-09-23-02，健康接口正常。

新工具取消目录交互输入：优先读取实例属性，空值时只读SQL实例BackupDirectory配置；要求Windows绝对路径并拒绝命令文本和非法字符，随后用独立升级身份检查目录存在，才开始COPY_ONLY/CHECKSUM及VERIFYONLY。备份入口、目录验证、备份执行和验证各自先记录阶段，备份失败不能误认只读预检失败重试。不沿用旧环境备份目录，也不创建目录或提高权限。

现场只读获得SQL实例配置目录，但日常运行身份未证明目录可访问；必须通过升级身份实际核验。无效路径测试RED退出1、GREEN退出0，目录回退/完整备份验证调用/缺失目录停止共3例及游标回归全部退出0，审查无阻断。旧失败记录及备份保留，重新执行程序备份准备后再请求现场输入未保存的升级凭据；不将备份失败视为导入成功。

SQL属性版本依据：[微软SERVERPROPERTY说明](https://learn.microsoft.com/zh-cn/sql/t-sql/functions/serverproperty-transact-sql?view=sql-server-ver17)，InstanceDefaultBackupPath适用于SQL Server 2019及以后版本，不能要求SQL Server 2017返回该属性。
