## 现状与实现

- 原实现为 ValidateUser 账号密码认证，HTTP Cookie 会话；每次同步独立客户端。
- 目标为官方 Python SDK 3.0.0 的请求签名认证（AppID、AppSecret、账套、用户）。SDK 来源为金蝶官方资料包，使用其 InitConfig / BuildHeader；HTTP 传输沿用 httpx，保留原请求格式、超时和保存结果不确定保护，不使用 SDK 自动重试保存。
- 应用签名不等同于 OAuth AccessToken；SDK 也有 Cookie/Session 处理。按用户确认的命名用户许可规则规划一个集成账号，不承诺免许可。
- K3_AUTH_MODE 显式选择 app / password，不自动降级。环境变量优先于后端 `.env.local`，后者忽略提交且权限为 600。原密码仅迁入受保护配置作为显式回退凭据。
- 应用模式的连接检测使用带签名的辅助资料空结果查询，避免只初始化 SDK 就报告连接成功。查询认证失败或非法响应须终止同步，不能当成“数据不存在”。
- 账号替换后重启进程，新客户端读取新配置；无跨账号全局会话缓存。
- 目标表单 BOS_ASSISTANTDATA_DETAIL，类别 xsxm；字段映射、PMS 权限入口、日志与保存三态不变。
