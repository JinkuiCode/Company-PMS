## 现状与纠正

当前 `project.py` 的档案及项目范围查询已按组织产品线和人员/部门限制；`business:data:all` 是可撤销的全部业务数据授权。旧类别授权上下文、角色字段、辅助依赖和服务筛选参数仍存在，当前业务 API 未引用旧类别授权依赖。不能把残留代码描述为所有业务接口仍按类别授权。

当前新增档案会调用 ERP 入队；修改编号或名称也会入队。现有 historical 状态及 kingdee_initial 来源不能直接代表本批线下导入，必须增加明确的来源和同步策略。

## 字段设计

### 复用字段

项目编号、名称、客户、设备系列、设备序列号、联系人、电话、详细地址复用已有字段。原客户简称写入 customer；另设 customer_full_name 保留原客户名称列，二者不自动覆盖。地点原文写入详细地址，不猜测省市。

设备系列继续使用现有枚举，通过预检列出原值到枚举的映射，不按名称相似程度自动合并。产品线复用 business_product_line_id，首次导入为 NULL。

### 新增字段

|业务字段|字段键|类型及规则|
|---|---|---|
|档案类别|archive_category|可维护数字枚举：主机、辅机、C类、D类、AS类、BS类、免费、待分类|
|客户完整名称|customer_full_name|可空文本，保留原客户名称列|
|机型|machine_model|可维护数字枚举；38 种原写法分别保留，未经确认不合并|
|数量|quantity|可空十进制数，保留精度，不把缺失转成零|
|单位|quantity_unit|可维护数字枚举；EA、PCS、个分别保留，疑似错字保留在预检中|
|销售公司|sales_company|可维护数字枚举|
|原台账状态|legacy_archive_status|可维护数字枚举，保存原有节点名称，不驱动项目进度流程|
|编码日期|legacy_code_date|可空日期|
|原台账更新日期|legacy_updated_date|可空日期，不覆盖系统审计时间|
|交期说明|delivery_note|可空文本|
|备注|remarks|可空长文本|

枚举使用现有 enum_registry 数字流水，修改显示名称不改变存储值，引用中的选项不能删除。档案类别不复用产品类别，也不构成新的权限维度。空值不生成“空”枚举。

来源、批次、追溯ID、原编号和原行号为系统只读信息，不混入业务枚举；保存在独立导入批次及明细记录中，并能从档案回查。

### 产品类别停用

- 移除项目档案、项目进度中产品类别的新增编辑入口和默认展示、筛选选项；失效列偏好按现有机制清理。
- 停用产品类别枚举维护入口以及角色类别授权入口、类别授权上下文和运行时辅助路径。
- 历史数据库列及其值保留，不删除历史迁移，不把历史值自动转换为产品线或档案类别。
- 写接口明确拒绝新增/修改产品类别，不能仅在前端隐藏。
- 现有项目/档案联动不再传播产品类别。旧字段仅为兼容读取留存，字段目录标记历史停用。
- 权限测试必须证明旧类别配置不影响访问；授权产品线、人员/部门范围、按钮权限仍然生效。空产品线授权不代表全部数据。
- 此条为用户对项目旧规则中“校验产品类别范围”的明确修订，后续规范同步记录这一变化。

## 同步设计

- 新增同步策略 erp_sync_policy，值 auto 或 manual。既有档案默认 auto，保持原行为；本批线下档案为 manual。
- 新增来源 offline_initial。现有 pms、kingdee_initial 的含义不变，不伪装为金蝶期初档案。
- manual 档案创建、编辑、批量分配产品线、导入均不得调用入队，也不得被后台扫描自动发送。
- 增加明确的“同步金蝶”动作。操作权限、产品线及人员/部门范围均由后端检查，不能因历史来源绕过。
- 手动同步成功后仍为 manual，后续修改仍需要用户再次点击。
- 同步前要求名称、启用状态、产品线及组织目标有效，执行已确认字段规则；缺失时返回可读原因，不向金蝶发请求。
- 手动同步复用现有队列、锁、保存提交审核、占用提示和结果核查。金蝶被占用时明确提示“请在金蝶端退出当前单据后，再次点击同步”，不自动重试此类失败。
- 新字段不扩大金蝶写入字段范围。只同步现有对接已支持的项目标识和名称等字段。
- 已有金蝶期初、已同步记录的编号和组织保护继续有效。
- 区分“仅归档/手动同步”策略与执行状态，不能把未发送资料显示成已同步。保留原金蝶历史状态的语义。

## 期初导入和批量维护

采用管理员批次预检及确认导入流程，首次目标只覆盖批准的第四版，不同时开发通用任意 Excel 映射器。

1. 校验文件哈希、表头、3024 个来源ID、编码唯一性、类型、长度、枚举映射、现有库编号和序列号碰撞。
2. 同一文件哈希与来源ID用于幂等保护。再次导入已完成批次只返回既有结果，不新增重复记录。
3. 与已有档案碰撞的记录列入预检阻断，不按名称或编号自动覆盖、改号或绑定。必须形成具体处理结果后才能继续。
4. 6 条名称缺失的历史记录允许 NULL 归档。只对 offline_initial 提供明确的导入例外，普通新建仍要求名称。历史空名记录维护其他字段应允许，手动同步必须补名称。
5. 无意义字符及现有空值按 NULL 导入。仍有业务含义的异常值不猜填，在批次问题清单中保留；数量不识别、错写日期可以为空，不伪造。
6. 所有记录初始 product_line_id、负责人等未提供归属保持空。拥有明确 business:data:all 和对应页面/操作权限的用户可整理未归属档案，普通用户不能因此看到全部历史数据。
7. 批量分配产品线有独立操作权限，校验目标产品线启用、逐条当前访问范围和并发修改；不触发金蝶同步。已同步/金蝶来源组织锁定规则不放宽。
8. 记录每条导入、字段变更及批次结果的统一操作日志，敏感字段脱敏。
9. 数据写入采用可回滚事务，失败不留下半批次；正式规模在测试库验证锁与执行耗时。回退仅允许删除该批次创建且未被修改、引用或同步的记录；其余列出阻断，不强制删除。

## 页面与接口边界

- 复用当前项目档案标准列表、字段治理、枚举控件和已确认抽屉，不重做全局表单。
- 新增字段纳入 field_catalog、field_policy、枚举注册、Schema、前后端列表和详情映射，同一份元数据控制显示与编辑。
- 原台账状态只在档案中展示，不替换现有项目进度状态；导入不自动创建项目进度或任务。
- 历史导入例外必须由后端明确的来源和批次路径控制，禁止客户端随意指定来源绕过必填规则。
- 增加手动同步和批量产品线分配动作；继续使用现有日志、统一错误处理和并发控制。
