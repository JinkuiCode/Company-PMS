# PMS 统一表单框架设计

## 1. 目标

PMS 建立一个仓库内部的、可独立升级的表单基础模块，统一普通表单、详情抽屉行内编辑和 AG Grid 单元格编辑的视觉语言、状态规则和键盘交互。

本次改造要解决的典型问题：

- 展示态、悬停态和编辑态的容器尺寸不同，切换时框体和文字跳动。
- Element Plus 外层、内层输入元素和全局焦点样式重叠，出现重影和双焦点框。
- 项目档案与项目进度分别维护相似的字段结构和 CSS，修复无法自动覆盖后续页面。
- Windows 和 macOS 字体渲染、系统缩放和浏览器焦点表达不同，缺少可量化的跨平台验收基线。

## 2. 范围与边界

### 包含

- 文本、选择、树形选择、日期、数字、长文本、开关、单项/多项勾选和分段选择等现有基础字段。
- 默认、悬停、编辑、焦点、错误、禁用、只读和加载状态。
- 标签、必填标记、帮助、错误、只读原因和保存状态。
- 新增/编辑表单、详情抽屉、表格单元格三类容器。
- 项目档案、项目进度、系统管理、认证及辅助页面的分批迁移。

### 不包含

- 不更换 Vue、Element Plus 或 AG Grid。
- 不修改后端数据模型、API 语义、RBAC、字段规则、枚举规则、OA 或 ERP 流程。
- 不建设动态表单设计器，不让业务用户在页面上自由生成组件。
- 第一版不拆成独立 npm 包；通过稳定公共导出和命名空间实现仓库内独立升级。

## 3. 视觉方向

延续 PMS 已确定的浅色、紧凑 B2B SaaS 风格，不重做导航、列表和品牌色。表单新增一套更明确的语义化令牌：

- 密集行内字段高度 `32px`，标准表单控件高度 `36px`。
- 字段内容水平内边距 `10px`，文字行高 `20px`。
- 展示、悬停和编辑状态的外容器尺寸不变，文字 x/y 坐标变化不超过 `1px`。
- 详情抽屉默认优先阅读；可编辑字段悬停时只出现浅灰背景，编辑时只有一层淡靛蓝外容器。
- 新增和集中编辑表单始终显示输入边界，用于表达“正在填写”。
- AG Grid 编辑器覆盖完整单元格，不在原单元格内再嵌套输入框。
- 项目内置 `Noto Sans SC` 作为首选字体，Element Plus、AG Grid 和原生控件继承同一字体令牌。

## 4. 模块架构

计划新增 `frontend/src/form-system/`，只通过 `index.ts` 暴露稳定公共接口。

### 令牌层

- `form-tokens.css`：尺寸、间距、边框、背景、焦点、错误和动效令牌。
- 所有颜色继续引用 `pms-theme.css` 的 PMS 语义色，不创建第二套颜色系统。

### 字段原语组件

- `PmsControlShell`
- `PmsTextControl`
- `PmsSelectControl`
- `PmsTreeSelectControl`
- `PmsDateControl`
- `PmsNumberControl`
- `PmsTextareaControl`
- `PmsSwitchControl`
- `PmsCheckboxControl`
- `PmsCheckboxGroupControl`
- `PmsSegmentedControl`

原语组件统一 `modelValue`、`disabled`、`readonly`、`required`、`loading`、`error`、`placeholder` 和可访问性属性。它们包装 Element Plus，业务页面不直接依赖 Element Plus 内部 DOM 类名。

### 场景适配器

- `PmsFormField`：标准新增/编辑表单，标签在上，可组合分组和错误导航。
- `PmsInlineField`：详情抽屉行内阅读与编辑，展示/编辑共用同一容器几何尺寸。
- `PMS_AG_GRID_FORM_CLASS` 与 `mergePmsAgCellClass()`：为 AG Grid 提供整格编辑命名空间和值呈现适配，保留现有编辑器、值归一化和自动保存。

三种场景共享原语、令牌和状态定义，但不共用一个巨型容器。

## 5. 交互合同

- 详情抽屉只有点击具体字段值才进入编辑；点击标签或行空白不进入编辑。
- 行内单行字段使用 `Enter` 暂存、`Esc` 取消；长文本使用 `Ctrl/Cmd + Enter` 暂存。
- 抽屉底部统一保存所有草稿，关闭时保留未保存确认。
- 标准表单提交时一次展示全部错误，滚动并聚焦第一个错误字段。
- 错误消息放在字段下方，尺寸变化由容器自然吸收，不覆盖后续字段。
- 禁用字段表示当前不允许操作；只读字段表示数据来源不在当前页面，两者语义不混用。
- 只读引用字段继续严格遵循 PMS 现有字段来源规则。

## 6. 分批迁移

1. 样稿验收：审查 `docs/prototypes/pms-form-system-v1.html`，确认视觉和交互。
2. 基础模块：实现令牌、原语组件、场景适配器和组件级测试。
3. 项目档案试点：先迁移新增表单和详情抽屉，验证 ERP、RBAC、字段规则和枚举。
4. 项目进度：迁移详情抽屉和表格自动保存编辑器。
5. 系统管理：按用户、角色、枚举、字段规则分批迁移。
6. 认证与辅助页：最后迁移登录、SSO 和低频辅助表单。
7. 收尾：清除已迁移页面的私有表单样式，更新 PMS UI 标准。

每一批都使用独立提交，不通过一次性全局 CSS 替换影响未迁移页面。

## 7. 验收标准

### 视觉

- 展示、悬停、编辑状态的容器高度、宽度和文字起点不变，文字位移不超过 `1px`。
- 任何字段只显示一层边界或焦点环，无重影和内嵌小框。
- 标签、值、占位符、必填、错误和只读表达在所有页面使用同一字号、颜色和间距层级。
- 抽屉内容独立滚动，底部保存操作始终可见。

### 功能

- 现有新增、编辑、草稿、自动保存、唯一性校验、必填、枚举、RBAC、字段规则、操作日志和 ERP 同步行为不变。
- 引用、计算和系统字段不能因组件迁移被错误放开编辑。
- 键盘顺序与视觉顺序一致，焦点清晰可见，无 `tabindex > 0` 干预。

### 跨平台

- macOS Edge，浏览器缩放 100%。
- Windows Edge，浏览器缩放 100%，系统显示缩放 100% 和 125%。
- 核心页面在 `1366x768` 和 `1600x900` 视口下检查截断、滚动、浮层定位和底部操作区。

## 8. 风险与回滚

- 最高风险是迁移时改变原有保存和权限语义。组件只接管表示与交互，业务提交函数保持原路径。
- 通过命名空间限定新样式，未迁移页面继续使用旧实现，避免全局污染。
- 每批独立提交并逐批验收；任何一批失败都可单独回退，不要求撤销已验收批次。
- 服务器部署在开发机全部验收后单独进行，部署前保留可回退副本。
