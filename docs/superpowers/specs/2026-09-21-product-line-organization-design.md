# 产品线、金蝶组织与项目数据权限设计

日期：2026-09-21。阶段：整体方案已确认，书面规格待复核，尚未实施。

## 1. 已确认的业务规则

- 产品线来源于金蝶组织，PMS 维护实际使用的组织及自己的显示名称。
- 第一版一个 PMS 产品线对应一个金蝶组织，同一组织不能重复配置。
- 用户明确确认不存在跨组织代采购或入库。
- 角色勾选产品线，用户取所有启用角色的产品线并集；没有勾选即没有权限。
- 产品线权限覆盖项目档案、项目进度及项目相关报表；新建只能选本人有权限的产品线。
- 原本人、部门及子部门等范围继续生效，与产品线范围取交集。
- 产品类别保留为业务字段，不再作为第二套产品线授权规则。
- 系统管理员也执行明确授权，不设置角色编码全权绕过，不在重启时补回撤权。
- 采购报表已获用户验收；本批改变其数据隔离方式，不重新设计已确认报表布局和数量公式。

## 2. 当前实现与变更边界

当前角色 `product_category_ids` 控制产品类别范围，空值表示不限；档案 `product_line_id` 仅指向 Bench、Single 等枚举。两者不能直接改名后当作组织权限。

当前采购报表通过可见档案的项目编码过滤；全部数据且产品类别不限的账号可跳过项目过滤。本批取消这种跳过组织限制的路径。申请日期仍限定 2026-01-01 起，分页、数量口径、列设置及查询方案保留。

本批不修改 OA 登录协议，不解决已单独搁置的 OA 认证问题；不修改金蝶项目基础资料编码/名称/备注映射，不向金蝶写组织或组织名称。

## 3. 产品线主数据

新增独立产品线主数据及角色关联关系，不将组织权限塞进自由枚举值。

产品线记录包含：PMS 内部流水 ID、金蝶数据源标识及组织内码、组织编码、原组织名称、PMS 显示名称、启用状态、排序、创建与修改审计信息。组织内码在数据源内唯一；组织名称只用于展示，不作为连接键。

- 新增时从金蝶组织候选中选择，默认将原名称作为显示名称，允许修改显示名称。
- 组织候选只供具有产品线配置权限的人员读取，支持编码/名称模糊搜索和分页。
- 普通业务下拉只返回已纳入 PMS、启用且当前用户获授权的产品线，不直接枚举金蝶全部组织。
- 金蝶原名称刷新不覆盖 PMS 自定义显示名；数据源异常不清空既有配置或撤销已有授权。
- 已被档案、角色等引用的产品线禁止删除。组织绑定创建后不可修改，改归属通过新建正确产品线和受控迁移处理。
- 禁用阻止新增和变更选入；拥有授权的用户仍可查看、维护历史档案其他字段。历史值保留显示名称。
- 被外部系统停用或无法确认有效性的组织不能新增纳入或新建选用，不自动猜测替代组织。

产品线从普通“枚举管理”退出，改由独立候选接口驱动；更新字段目录和选择来源声明，不把旧枚举编号解释成组织或新主数据编号。此为已确认组织映射方案对原通用枚举规则的明确例外。

## 4. 角色和后端授权

新增角色-产品线关联表，唯一约束为角色 ID 与产品线 ID。授权上下文返回明确的产品线 ID 和组织 ID 集合，不使用空值表示全部。

- 多角色按钮权限取并集、本人/部门范围沿用现有最宽规则，产品线取并集；最终对象必须同时满足按钮权限、部门范围和产品线范围。
- 不新增永久“自动拥有未来全部产品线”旁路；界面“全选”只勾选当前明确列出的值。
- 新建产品线不会自动授权给所有角色；管理员需明确保存角色分配。
- 禁用角色立即退出计算；权限不写入 JWT，后端下一次请求读取最新规则。
- 禁用产品线与禁用角色不同：前者保留已授权历史记录访问，后者撤销该角色提供的全部权限。
- 强制改密中的会话不获得业务组织权限。
- 未登录沿用现有认证响应，无按钮权限返回 403；具体对象超范围返回 404。
- 查询数量、候选、详情、导出、关联明细与写接口执行同一范围，不依赖前端隐藏。

产品线管理权限建议为 `system:product-line:view/add/edit/delete`；沿用角色编辑权限维护角色产品线。迁移和未归属清单另设明确的 `system:product-line:migrate` 权限，仅一次性授予当前系统管理员模板，不在启动时补回。

## 5. 项目档案与项目进度

档案产品线为项目归属的唯一来源；新建必填，不允许通过字段规则隐藏、取消必填或开放未授权选项。只有一个启用且获授权选项时默认带出；多个时主动选择；没有时阻止创建并给出清楚提示。

更新产品线同时校验原档案访问权、原产品线和目标产品线授权，目标必须启用；记录前后归属差异。修改后关联项目进度立即继承新归属，不保留独立可编辑副本。

项目进度通过 `archive_id` 关联档案。没有档案关联或档案尚未确定产品线的历史项目不回退到产品类别猜测权限，进入迁移异常清单。

覆盖列表、详情、新增、更新、删除、启停、任务写入、自动保存、批量操作、ERP 同步发起与重试、统计及导出。同步后台任务不能因为没有交互用户就跳过归属校验，也不以发起人的旧 JWT 作为持久授权依据；实施时按既有系统任务与操作人权限边界补全契约，不改既有金蝶写入目标匹配规则。

已同步档案若需改变产品线，先检查既有同步机制的组织使用方式及实际金蝶项目归属。不能证明改归属不会使外部资料不一致时，拒绝该归属变更并交由管理员处理，不盲目转移金蝶资料。

## 6. 项目相关报表

有效报表范围为：当前用户可见的 PMS 项目归属 + 对应金蝶组织。即使数据范围为“全部”，也必须通过明确组织授权。

- 采购申请为主表粒度，按实际数据库验证过的申请归属组织及项目编码限制。
- 订单、入库、收料中间链和退料逐级验证项目、组织及来源明细关系；不得只限制主表。
- 申请、采购、收料等组织字段可能不同名，不能仅按字段名相似直接套用。只读核对物理表、字段和样本后形成字段映射表，列明每张单据采用的归属字段及理由。
- 用户已确认不存在跨组织代办，因此发现不同组织或无法归属的关联时，标记为待核对；不把其他组织单据、供应商、物料或数量暴露在明细中，不把排除后的部分数量冒充完整合计。
- 涉及异常的合计沿用报表现有“无法确认则不计算”的策略，不显示成正常零值或已完成。
- 未映射到 PMS 档案/产品线的项目不进入普通报表，也不因系统管理员身份自动开放；通过受控迁移清单整理。
- 总数、列表、筛选候选、汇总、详情及导出统一应用限制；授权过滤必须早于分页。
- 保留金蝶只读账号。组织元数据或归属字段需要增加读取权限时，只增加经核对的表/列 SELECT，独立执行授权，不扩大为全库读取或写入权限。

## 7. 历史迁移与发布顺序

1. 只读核对金蝶组织与单据归属字段，生成组织候选和项目归属检查结果。
2. 开发机完成产品线主数据、角色授权、对象过滤和迁移工具；使用构造数据验证多组织隔离。
3. 生成待确认清单：旧产品线、项目编码、候选组织、证据及异常分类，以及旧角色范围与新产品线授权对照。
4. 用户确认具体组织选项、显示名、历史映射和角色分配后，形成固定迁移清单；不按 Bench/Single 名称或旧枚举数字自动猜映射。
5. 独立升级需有效备份及批准。部署时在 PMS 维护阶段完成结构升级、迁移、角色分配、验证，再开放服务；不使用暂时允许全部组织访问的过渡开关。
6. 普通历史记录未归属则默认不可见。具有迁移权限的管理人员可在单独清单中处理，不将该能力变成正常业务接口的权限旁路。
7. 检查至少一个有效管理员保有角色与产品线配置权限；未完成约定映射或授权的发布不能标记完成。

旧产品类别授权和枚举数据保留迁移证据，不直接清空；新归属使用独立字段或明确映射迁移，避免旧 `product_line_id` 数字碰巧等于新主数据 ID 而产生错误授权。数据库版本随结构/初始化变更提升；正常启动只检查，不执行迁移。

回退使用发布前程序与数据库备份配对处理；启用新权限模型后不得直接运行旧版较宽松授权代码。不得重启共享 SQL Server、OA 或服务器，仅允许按批准重启 PMS。GitHub 推送、主分支合并和服务器最终部署仍分别遵守原批准边界。

## 8. 页面与接口

- 新菜单“产品线管理”，路由 `/system/product-line`；标准列表展示原组织与 PMS 显示名、状态、排序，新增/编辑使用统一“用户 B”抽屉。
- 角色抽屉将产品类别范围替换为产品线复选列表，明确未选即无权限；已禁用产品线展示标识，允许移除已有历史授权。
- 档案新增/编辑、项目筛选等使用专用受控产品线选项接口，进度产品线为引用只读字段。
- 接口按产品线 CRUD、受控业务选项、受控金蝶组织候选、迁移检查分离；不向普通业务用户返回完整组织配置。
- `/api/auth/me` 返回新的产品线范围；前端路由切换、刷新及 403 后更新授权，后端始终以数据库即时结果为准。
- 既有筛选/查询方案中失效的产品线或旧产品类别权限条件按元数据清理并提示，不能因非法条件被丢弃而跳过后端组织限制。
- 新字段纳入字段目录；配置修改、角色授权、档案归属变化和迁移均写统一中文差异日志。组织来源故障、重复绑定、引用删除、并发覆盖均有明确错误，不泄露连接凭据。

## 9. 验收标准

- A 组织用户看不到 B 组织档案、进度、任务、报表、候选、总数及导出；直接请求 ID 也拒绝。
- 多角色、未勾选、停用角色、实时撤权、管理员撤权、全部数据但组织受限均符合规则。
- 创建只允许获授权的启用产品线，伪造请求拒绝；修改归属验证两端权限。
- 重命名不改变组织关联和角色授权；停用保留历史展示，引用值不能删除。
- 跨组织异常链路不泄漏明细、不伪造完整合计；无映射项目默认不可见。
- 历史映射幂等、失败回滚、旧枚举 ID 碰撞不会误授权；重启不回补撤权。
- 报表已验收的分批订单、分批入库、退料数量及主从联动保持正确；查询方案、分页、导出与新权限共同测试。
- 执行 RBAC、字段目录、枚举、数据库升级、项目档案/进度、ERP 同步、操作日志、采购报表及前端标准契约与构建；使用真实组织样本只读复核后再做业务验收。
