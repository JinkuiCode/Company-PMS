# 全系统统一查询工作区实施

基线：用户已确认 query-defaults、query-reference 和列漏斗 A 样稿；2026-10-11 明确实施顺序为档案、三个报表、其他列表。复用 codex/pms-unified-query，不部署、不合并、不推送。

## 模块边界

- query-system/workspace.ts：真实用户/列表隔离的方案存储、唯一默认、临时条件、必输与空值校验。
- PmsQueryConditionRow.vue：三段条件控件，复用现有表单及 PmsQueryReference（跨搜索选择、Excel 粘贴）。
- PmsQueryWorkspace.vue：方案选择、设置、查询、重置、添加同一行；设置抽屉保存默认显示/值/顺序，不保存临时状态和列筛选。
- 列漏斗与适配器：已提交条件和列条件分别保存，服务端结果在分页前筛选，汇总列在聚合后筛选。业务页只提供字段、默认条件、接口、布局偏好。

## 风险与边界

保留旧方案存储不删除；不扩大菜单/查看/导出/产品线权限，不修改 OA、金蝶写入、同步、业务数据或数据库结构。真实身份来自 auth store，不接受任意用户参数。元数据未就绪时不能加载空目录覆盖方案。旧异步响应不能覆盖新草稿。报表进入不自动查业务数据。各批如尚未完成，不以试点替代全系统完成。
