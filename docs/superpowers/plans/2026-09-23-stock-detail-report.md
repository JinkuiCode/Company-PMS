## 分批实施

### 1. 来源矩阵与数量计算

新增 `backend/app/services/stock_detail_sources.py`，按DLL实际注册来源建立物理表、组织字段、物料字段、日期、库存更新标志、方向、数量字段及关联键矩阵。先做静态解析，不执行DLL或它生成的写入临时表语句。涉及未确认表结构，集中准备一次元数据检查，避免逐表要求输入凭据。

新增 `backend/tests/stock_detail_report_contract.py`：先验证纯空格必填、非法日期、越权组织、未知仓库、相同物料跨组织、直接调拨双方向、自动生成单据排除、退货符号、非1:1单位换算、多库存维度、非零期初及跨页结存。观察测试失败后实现对应读取与计算，不写只复述实现的测试。

新增 `stock_detail_reader.py` 与 `stock_detail_fields.py`：参数化查询和稳定排序；按组织、物料、仓库、货主、库存状态及所需库存维度计算，保持Decimal精度。期初使用合适结存基点加查询开始前变动；不得只取最近一条快照或默认零。先汇总与计算结存再分页；筛选不得静默移除影响结存的流水。

### 2. API与权限

新增 `backend/app/api/stock_detail_reports.py`：`/api/reports/stock-detail` 列表、`/metadata` 字段和组织、`/options` 物料和仓库候选。物料输入只搜索有权范围，空输入422；仓库使用ID，不接收任意显示文字作为SQL条件。候选不依赖即时库存非零记录，避免漏掉已经清零仓库的历史。

权限码 `report:stock-detail:list`、`report:stock-detail:view`、`report:stock-detail:export`；运行时检查现行权限。空组织授权不连接数据源，越权与无效候选失败关闭，错误脱敏503。接口不返回财务字段。

新增 `stock_detail_migration.py` 并接入 `database_revision.py`、独立升级入口及迁移契约；首次授权模板可编辑、撤权不回补。正式库升级仍待独立批准。

### 3. 页面与后台导出

新增 `frontend/src/views/reports/StockDetailList.vue`、`frontend/src/api/stockDetailReport.ts`，接入路由及菜单图标。复用 `PmsDataList`、统一字段控件、现有列偏好；输入必填提示与后端错误一致。物料与日期变化重新查询，方案恢复同样走验证，旧请求不得覆盖新结果，失败不得将旧数据冒充新结果。

接入 `backend/app/services/report_export_jobs.py` 与 `report_export_data.py`，沿用后台Excel流程、权限复核和操作日志；导出全量当前条件，期初及所有流水同一口径，不添加1万条截断，不混加不同物料或单位。列表列隐藏不改变授权范围。

### 4. 验证及交付

- 测试：新增reader/API/迁移/导出契约，回归库存、采购、数据权限、字段目录和现有导出。
- 前端：`node tests/style-contract.test.mjs`、`node tests/list-standard-contract.test.mjs`、`node tests/system-ui-consistency-contract.test.mjs`、`npm run build`，新增报表交互测试。
- 浏览器：1600/1366/390宽度；必填、仓库候选、方案恢复、列设置保存、分页、数量固定区、明细联动、异常与空结果、导出。
- 真实只读对账：截图六笔基准，再扩展退料/退货、普通入出库、非零期初、多仓库及跨组织调拨。来源未覆盖不得报告完整上线。
- 性能：限定物料及日期后记录真实响应时间和读取规模；不得用模拟计时替代正式库性能。
- 编写 `docs/物料收发明细报表说明.md`，逐字段注明取值逻辑、方向、单位、期初基点、排序及权限；更新 `change.md`，分别报告开发、授权、数据库升级和部署状态。
