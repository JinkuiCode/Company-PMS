# 用户、角色与枚举表单会话接入

> **For agentic workers:** 使用executing-plans在当前已批准工作区逐项执行，独立审查按requesting-code-review，不委派实现、不新建工作树。

**Goal:** 完成这三处既有维护表单适用的共享会话迁移，随后汇总可审阅的下一阶段交付清单。

**Architecture:** 复用useFormSession及既有PmsFormDrawer，业务API/授权不改。用户资料与重置保持独立；角色菜单/产品线选择纳入同一内存草稿，树完整初始化后建立基线；枚举固定提交目标和系统存储值约束，刷新失败不误当持久化失败。

**Tech Stack:** Vue3/TypeScript、Element Plus、统一控件、Playwright全API模拟。

- 延续已批准治理方案、旧页分批接入及用户“继续按顺序执行”。保留codex/pms-unified-query、混合工作区；无真实写入/授权、业务后端或认证规则变更、数据库升级、正式环境/金蝶/邮件或Git动作。说明配套仅在runtime_release.GUIDES登记roles/enums，接口结构、发布权限和通知流程保持；补登记一致性契约及发布/邮件隔离回归。
