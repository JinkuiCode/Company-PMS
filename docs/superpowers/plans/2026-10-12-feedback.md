# 问题提报方案 A Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for inline implementation, or superpowers:subagent-driven-development if the user selects delegation. Follow the existing approved endpoint; do not merge, push or deploy.

**Goal:** 在开发机实现独立的问题与需求提报、管理员跟进、分类统计和可靠邮件通知。

**Architecture:** 采用已确认方案 A 的标准列表与详情抽屉，复用统一查询、表单、分页、列过滤与操作日志。后端独立业务模型和有效权限控制本人/全部范围，分类注册为稳定数字枚举。业务保存和通知入队同事务，后台邮件发送不影响业务保存。

**Tech Stack:** Vue 3、TypeScript、Element Plus、FastAPI、Pydantic、SQLAlchemy；SQLite 开发、MSSQL 2017 生产；Python 标准库 SMTP。

## Global Constraints

- 唯一视觉基线：frontend/prototypes/feedback.html?variant=A；不实施 B/C 信息架构。
- 用户必须主动选择类型、模块、类别、影响；所有必填输入初始化为空。
- 查询使用 PmsQueryWorkspace，列表使用 PmsDataList；表单使用 PmsFormDrawer 与统一字段组件，不移植样稿简化控件。
- 24px 查询、32px 编辑、32px 数据行；表头居中；语义色及字体继承全局令牌。
- 不改 OA、ERP、现有项目权限；独立权限和开发机实际升级已获本批授权。
- 不部署服务器、不合并 master、不推送；既有未提交文件不撤销。
- SMTP在已有参数设置中配置，密码隐藏输入、加密存储且不回显，不写日志；未配置时不发送真实邮件。
- 附件5个/单、10MB/个；有效查看及处理全部提报权限的启用用户作为管理员收件人，已批准。

## 文件职责

- backend/app/schemas/feedback.py：提报、补充、处理输入及跨字段校验。
- backend/app/models/feedback.py：提报、跟进、附件、通知持久化。
- backend/app/services/feedback_enums.py：分类初始值与字段绑定；enum_registry.py 接入引用计数。
- backend/app/services/feedback.py：本人范围、提交、补充、乐观版本处理、统计。
- backend/app/services/feedback_mail.py：通知入队、有效收件人、SMTP、原子领取、退避重试；不打印邮件内容或凭据。
- backend/app/services/feedback_attachments.py：文件类型/大小/数量、隔离存储、授权下载。
- backend/app/services/feedback_migration.py：限定版本升级、一次性菜单及授权，不重建已撤销权限。
- backend/app/api/feedback.py：接口 RBAC、分页500、查询v2、导出、附件及重试。
- frontend/src/views/feedback/FeedbackList.vue、FeedbackDetail.vue、FeedbackForm.vue：A列表、详情、统一表单。
- frontend/src/api/feedback.ts、frontend/src/feedback/model.ts：接口类型与空草稿/字段映射。
- backend/tests/feedback_{input,service,mail,upgrade}_contract.py、frontend/tests/feedback-contract.test.mjs：目标行为回归。
