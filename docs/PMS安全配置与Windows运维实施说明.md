# PMS 安全配置与 Windows 运维实施说明

## 本次开发机已完成

- 源码中的数据库密码、JWT、OA/SSO 和金蝶敏感默认值已移除。
- 无配置时使用 SQLite、关闭 SSO 和金蝶只读的安全开发默认值，不再默认连接公司内网服务。
- 后端启动前统一校验运行配置。生产模式缺少数据库、JWT、OA/SSO 或金蝶必要项时直接停止，错误只列字段名。
- 本地启动器共用项目根目录受保护配置，并在首次使用时生成本机 JWT 密钥，不显示密钥内容。
- Windows 运维模块覆盖启动、停止、健康检查、日志轮转、计划任务注册和部署前备份。
- 发布包构建工具已纳入安全配置模板和 Windows 运维模块。

## 正式服务器待执行

以下操作没有在本次开发机工作中执行：

1. 只读核对 `C:\PMS` 当前运行来源、Python/Nginx 路径、计划任务和受保护配置键是否齐全。
2. 在受保护配置中加入生产模式标记，通过配置检查后再重启服务。
   OA 端 `pms_sso.jsp` 同步改为从 OA Java 运行环境的 `PMS_SSO_SECRET` 系统属性或环境变量读取共享密钥；未先配置时不得替换正式 JSP。
3. 复制运维模块，按现场路径生成 `pms-operations.json`，先手工启停与健康验收，再安装计划任务。
4. 在维护窗口执行一次服务器重启验收，检查 PMS 直连、OA SSO、权限、档案/进度读取和金蝶连接。
5. 继续执行 SQL Server `COPY_ONLY`、`CHECKSUM` 和 `RESTORE VERIFYONLY`；恢复演练只能使用独立测试数据库。

## 密钥轮换边界

源码中曾出现过的敏感值应视为需要轮换，但不能在普通代码发布中一起盲目更换：

- JWT 密钥轮换会让现有登录失效。
- SSO 共享密钥必须同时更新 PMS 与 OA 端 JSP。
- OA 端 JSP 不再保存共享密钥明文，正式值由 OA Java 运行环境注入。
- OA 应用密钥需在认证中心更新并立即验证回调。
- 数据库密码需要同步更新 SQL Server 登录和受保护配置。

每项轮换都必须单独备份、单项修改、即时验证，失败时只回退该项。任何密钥均不得进入 Git、聊天、截图、命令参数或普通日志。

## 默认监控策略

健康检查每五分钟检查后端和 Web 入口，连续失败次数写入本地状态文件。第一版只记录并返回失败，不自动重启；这是为了避免网络短时抖动或外部依赖异常触发错误重启。稳定运行并补充通知渠道后，再单独批准自动恢复策略。
