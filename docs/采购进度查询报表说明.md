# 采购进度查询报表说明

状态：开发机实现与验证记录，2026-09-21；尚未部署服务器或完成业务人工验收。本文区分已验证结果与待验收事项，不作为正式上线证明。

## 1. 用途与页面

以采购申请明细行为查询单位，查看它关联的采购订单明细及采购入库明细。一张申请的不同物料行分别展示，不能按物料编码合并。

- 主表一行的唯一身份：申请单内码 + 申请明细内码；单号、行号供人员辨认。
- 查询范围固定为申请日期自 **2026-01-01 起（包含当天）**，列表、总数、明细、筛选候选及导出一致。日期筛选可继续缩小范围，不能扩大到 2025 年；不以订单或入库日期替代申请日期。符合范围的申请保留完整下游关联链，不分别截断订单和入库。
- 供应商筛选表示申请行存在该供应商的关联订单；主表仍汇总此申请行的全部可计入订单和入库，避免筛选后数量被误解为完整采购进度。
- 默认每页 50 条，筛选和排序在服务器执行后分页。查询方案恢复筛选、列设置和每页条数后回到第一页。
- 打开明细后，鼠标或键盘改变左侧选中行，明细同步切换；切换时立即清空上一行内容、订单筛选和错误，显示当前行加载状态。
- 每次明细请求绑定申请行唯一身份。过时响应不得覆盖当前行；关闭抽屉后不得由迟到响应重新打开。
- 明细中的订单表与入库表平铺展示。选择订单只过滤下方入库表；“查看全部”恢复当前申请的关联入库。
- 筛选或翻页使当前选中行离开列表时关闭明细，不能保留失去上下文的旧内容。

## 3. 主表字段取值

以下表名简写：申请头=采购申请表头，申请行=采购申请明细；订单头/订单行、入库头/入库行同理。汇总计算字段使用“累计”或差额名称，与原单据字段区分。

| 页面字段 | 来源及逻辑 | 空值或边界处理 |
| --- | --- | --- |
| 项目编号 | 申请行 `F_TWBJ_ASSISTANT_83G` 关联辅助资料 `FENTRYID`，取 `FNUMBER` | 不用辅助资料内码作为项目编号；不静默用代理文本代替 |
| 项目名称 | 项目编号精确匹配 PMS 项目档案，取 PMS 项目名称 | 未匹配或名称为空显示 `-`；不得用金蝶项目名称替代 PMS 名称 |
| 申请单编号 | 申请头 `FBILLNO` | 保留完整值，超出列宽省略并提供完整提示 |
| 申请单行号 | 申请行 `FSEQ` | 非关联主键 |
| 申请日期 | 申请头 `FAPPLICATIONDATE` | 按日期显示，不以创建日期代替 |
| 数据状态 | 申请头 `FDOCUMENTSTATUS`，由统一金蝶状态映射生成中文名称 | 未识别代码显示“未知状态”，不计入有效数量 |
| 关闭状态 | 申请头 `FCLOSESTATUS`，A 未关闭，B 已关闭 | 未识别显示 `-`；关闭不抹去历史有效数量 |
| 物料编码 | 申请行 `FMATERIALID` 关联物料主表，取 `FNUMBER` | 不作为单据间连接键 |
| 物料名称 | 同一物料的中文 `FNAME` | 中文缺失显示 `-`，保留物料编码列 |
| 规格型号 | 同一物料中文记录的 `FSPECIFICATION` | 空值显示 `-` |
| 申请单位 | 申请行 `FUNITID` 关联单位中文 `FNAME` | 汇总数量必须换算到本行单位 |
| 申请数量 | 申请行 `FREQQTY` | 原值展示，真实零显示 0 |
| 批准数量 | 申请行 `FAPPROVEQTY` | 空值不是零；未批准不能冒充待下单 |
| 累计下单数量 | 申请行对应的有效订单来源关联量，按当前有效数量汇总并换算为申请单位 | 不使用 `FBASEUNITQTYOLD`；多申请合并订单不得为每条申请重复计入整单数量 |
| 待下单数量 | 批准数量减累计下单数量 | 超额情况保留差额并标记，不能强制归零掩盖异常 |
| 供应商 | 已验证来源的关联订单头 `FSUPPLIERID` 取中文名称 | 多个供应商显示“多家供应商”，具体名称在明细查看；不复制申请行 |
| 最近订单日期 | 可计入订单头 `FDATE` 的最大值 | 无有效订单显示 `-` |
| 订单数据状态 | 已验证来源的关联订单状态去重显示 | 不随意取第一张订单的状态代表全部 |
| 累计入库数量 | 可计入入库明细的实际入库量，按来源归属申请行，再换算为申请单位 | 中间收料量不是实收入库量；无法归属时标记异常 |
| 累计退料数量 | 已核实来源的有效入库后退料量，按申请单位汇总 | 收料后、入库前的退料不能扣减实收入库量 |
| 累计净入库数量 | 累计入库数量减有效入库后退料数量 | 只有退料链路验证通过后才能输出可靠净值 |
| 待入库数量 | 累计下单数量减累计净入库数量 | 不沿用样稿中的“申请数量减入库数量” |
| 最近入库日期 | 可计入入库头 `FDATE` 的最大值 | 无有效入库显示 `-` |
| 入库数据状态 | 已验证来源的关联入库状态去重显示 | 不随意取第一张入库单的状态代表全部 |
| 采购进度 | 差额不可确认或出现超量为“数据待核对”；下单为零为“未下单”；待下单大于零为“部分下单”；其余待入库大于零为“待入库”，否则“已完成” | 关闭或终止不自动补齐数量；“已完成”只表示数量完成，不代表流程关闭 |

| 字段 | 来源 |
| --- | --- |
| 单据编号 | 入库头 `FBILLNO` |
| 行号 | 入库行 `FSEQ` |
| 入库日期 | 入库头 `FDATE` |
| 单据状态 | 入库头 `FDOCUMENTSTATUS` 对应中文名称 |

明细保留原单据数量和各自单位；主表累计量使用申请单位，两者不能在单位不同的情况下直接相加。来源不匹配或涉及其他申请的合并订单不展示原始明细，避免误读整笔数量及泄露其他项目资料；主表能证实的本申请下单分配量仍保留，无法归属的入库累计显示 `-`。

## 5. 关联与计算约束

1. 订单来源必须核对 `FSTABLENAME`、`FSBILLID`、`FSID`，对应申请表、申请表头内码和申请明细内码。仅凭物料、单号或行号不足以匹配。
2. 入库以 `FPOORDERENTRYID` 与关联表相互校验。中间收料单必须沿来源关系继续追溯；不能把收料当入库重复累计。
3. 订单、入库分别聚合到申请行，再连接主表；避免订单乘入库形成重复行导致数量放大。
4. 当前关联量和原始携带量不同，必须使用当前有效量。
5. 数量计算使用十进制定点精度。单位不同时核对基本单位及转换关系，不可直接相加；转换失败输出异常。
6. 单据中文状态及是否计入，需以金蝶业务定义和实际单据验收为准。草稿不算有效采购，作废不计入；关闭不应抹掉已经发生的下单和入库事实。
7. 无来源的订单不硬挂到申请；一个订单合并多条申请而入库来源不足以分配时，明确显示归属异常。

## 6. 权限、导出及性能

- 新增独立查看、导出权限，首次仅授权系统管理员；不设置角色编码全权旁路，不在重启时补回撤权。
- 受限用户以项目编号匹配 PMS 档案，沿用档案范围及产品类别限制；未匹配档案不对受限用户展示。
- 列表、总数、详情、筛选候选和导出执行相同权限范围，不能仅在页面隐藏。
- 导出按当前筛选且重新校验权限，写统一操作日志；表格文本需防止电子表格公式注入。
- CSV 单次最多 500 行，超出时明确提示缩小筛选范围，不截断后冒充全部数据。查看与导出权限必须同时具备。
- 支持申请单/物料模糊搜索、项目编号选择、供应商模糊匹配、申请日期及进度筛选；排序支持申请日期、申请单编号、项目编号、物料编码。
- 个人查询方案保存在当前浏览器、按 PMS 用户隔离，不是跨设备共享配置。
- 查询失败显示失败与重试，不伪装为“暂无数据”；加载时显示加载状态。
- 数据库连接、查询、导出设置超时及规模边界。不得为报表缓存或采样写入金蝶业务库。
